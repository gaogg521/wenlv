# D01 商品促销折扣：实施与验收

新增待办，**尚未实现**。GLM负责实施和自测，Codex独立验收；第三批优先接入，与成本利润展示及后续套餐联调。不替换已完成的自由豆满减体系，不建设新H5。

## 业务与配置

支持“原价299元、打8折、折后239.20元”。这属于商品促销降价，自由豆属于官方补贴券，两种能力分别配置与记录。

PC落在「商品与团期 → 促销折扣/价格规则」，运营/超管按既有模块及数据范围维护：活动名称、适用产品/团期/渠道、真实原价来源、折数、生效/失效时间、状态、早鸟价与商品折扣是否叠加（默认关闭）、操作原因、规则版本及审计。界面直接填“8折”，说明“按原价80%付款”，不能要求运营填8000bp，更不能把8折理解为只付8%。金额均按元展示。

游客列表、详情、预订及推广素材显示同源的原价、折扣/优惠价、生效条件与实时价格提示；不使用人为抬高的假原价。产品经营总览展示活动状态、折前/折后收入及毛利变化。停售、过期、不同团期或渠道不能靠直链接口绕过规则。

## 首版计算与叠加契约

1. 服务端统一试算和建单校验。折扣候选价取真实团期原价×有效折数；8折内部可表示付款比例8000bp。早鸟价是按提前预订时间条件生效的价格，商品折扣是针对商品定价的付款比例。两者提供独立叠加开关，**默认不叠加**：关闭时取有效早鸟价与原价折扣价中较低者；开启时先取生效早鸟单价再乘商品折扣，未命中早鸟则以真实原价计算。价格相同时优先保留既有早鸟规则。同一主商品最多采用一条折扣规则，不做多条折扣相乘。
2. 金额用整数分、折扣用整数比例；单位价四舍五入到分，再乘数量，前后端、支付和退款统一。折数必须大于0且不超过10，界面最多两位小数；折后应付不足支付最小金额不能默认为免费。
3. **自由豆与旅豆不互斥，允许同单使用**；分别记权益、预算和账本，不把自由豆换成旅豆或混入发行统计。不能沿用旧版同单互斥守卫，也不能用新增“默认不叠加券/旅豆”开关绕过此需求。早鸟/商品折扣开关只控制这两种价格规则，不控制自由豆与旅豆的并用。
4. 顺序为有效商品价格（早鸟/折扣）→自由豆门槛校验及满减→旅豆抵扣→最终现金实付。自由豆门槛按有效商品金额判断，不能用原价凑门槛；保费/代收款不参与优惠或凑门槛。旅豆按比例的经济计算锚定最终实际支付价，不按原价、划线价或券前金额。具体公式与回归见下节，不能暗中丢弃用户已选择的权益。
5. 促销降价只改变实际销售价，不自动产生59.80元的官方补贴应付，不向自由豆预算或旅豆账本塞一笔差额。若另有平台补差/参与方保额，需要明确承担方、预算来源及B04/B17资金契约后再启用。
6. 未开启折扣时原早鸟与旧单回归；新单同时遵循本次自由豆/旅豆并用及实付基数修正。试算与建单之间规则/价格变化要刷新并明确确认，不能悄悄提高应付；已建未支付订单保留其价格快照和原支付窗口，活动到期不改旧单金额。

## 旅豆实付锚定与实施差异（负责人最新纠正）

独立经济生态保留现有旅豆兑换关系、发行预算、费率配置值、余额及历史封存；本次修改的是新单优惠组合及比例的计价基数，不自行改发行规模或奖励率。示例按现有1旅豆抵0.10元，仅为计算说明，比例仍读参数中心。

- 设有效商品额G、自由豆优惠C、旅豆抵扣额B，最终商品现金X＝G−C−B；订单总现金另加保费/代收款。商品优惠和商品比例不将代收款算入销售收入；当前返豆读取`amount_pay`，GLM必须核对其中保费的处理并分清商品实付和总支付快照，不把字段名当已满足要求。
- 返豆、按现金计算的奖励/佣金使用最终实际支付的适用商品金额X及既有费率，不使用原价或G；原固定奖励规则保留。退款按原单快照冲回，不能按新费率重新发放。
- 抵扣上限如以配置比例r锚定最终实付，必须满足B≤r×X，同时受用户选择、余额及支付下限限制；禁止直接用G×r。因为X已经扣除B，应以整数分和整旅豆求解，不能先以券后未抵豆金额计算后称其为最终实付。上限可用`floor(r×(G−C)/(1+r)/每豆抵扣分)`推导，再用整数比例复核边界，避免浮点误差。
- 示例：299元8折G＝239.20，券C＝50，若抵扣上限r＝10%，可用172旅豆抵17.20，X＝172.00；17.20恰为最终现金172.00的10%。返豆按172.00及实际配置费率计算，不按299、239.20或189.20。若余额或用户选择不足则实际少抵，再按实际X算返豆。
- 现有代码差异：`api/src/domain/order.mjs`仍拒绝自由豆与旅豆同用，抵扣上限按goods算；`api/src/routes/freedom.mjs`试算返回beanDeduct为0；游客预订页选择券会清掉旅豆。`api/src/domain/bean.mjs`返豆已读amount_pay，但组合新单及金额组成尚未验证。**此节是待GLM实施/自测、待Codex验收，不能标成功能已完成。** 需要统一试算/建单、事务锁定与扣减、预算、支付幂等、取消/超时归还、全退/部分退、UI及旧测试；仅删除一个互斥判断不算完成。

## 订单、资金、退款和利润

订单快照至少保存原价、数量、有效早鸟/折扣类型、活动ID/版本、折数/比例、折后单价及商品金额、减价额、叠加策略、自由豆/旅豆、保费、现金应付及订单项分摊。不能只存当前活动ID再动态反查历史价格。

佣金、按现金计算的成长/分账等沿用真实实付入口，不用划线原价放大；原固定奖励不因增加折扣字段擅自改规则。毛利看板读取同一成交和成本快照，区分折前预计、折后预计与已确认结果。例如折后239.20元、直接成本180元，商品毛利59.20元、毛利率24.75%，不是299−180；佣金等额外费用及官方补贴另列，不冒充最终净利润。

全额退款只退实际收取现金；促销减价不是可退现金。自由豆的锁定/使用/归还/过期及预算继续复用现有域。套餐部分退款沿B04订单项不可变分摊，优惠、现金和补贴分别冲减、尾差可复算；已结算/已付款后走调整，不删除历史，不将原价作为退款金额。

## Codex验收清单

- 299元8折＝239.20元；前台“8折”与后台8000bp含义一致，非法折数/精度/负数被拒。
- 早鸟259与8折239.20取239.20；早鸟199与8折239.20默认取199；打开早鸟叠加时259×8折＝207.20、199×8折＝159.20；普通原价及无折扣旧单保持原行为并完成回归。
- 早鸟/折扣默认不叠加，开启后接口、价格页、建单、快照一致；自由豆/旅豆可并用，299→239.20→减50→抵172旅豆17.20→现金172.00（示例上限10%）；只有券且未选旅豆时现金189.20。保费不打折、不凑门槛，低于门槛的折后金额不可用券。
- 旅豆选择不足/余额不足、比例0及上限、整豆尾差、同用权益并发锁定、返豆基数、退款分别归还及无重复发放/扣减均有断言；不能靠更新断言掩盖资金不平。
- 生效前/后、到期、停售、范围越权、规则并发变更、重复支付回调、取消/超时、全退/部分退及已付款后调整，均有可复现测试。
- 新折扣/成本规则不改历史订单；收入、成本、毛利、佣金、自由豆责任、退款与结算能从同一快照复算。
- PC实际配置、游客列表/详情/预订/订单、推广素材及经营总览实际看图和操作；价格、长文案、金额对齐和错误状态均复核，不只改前端文案。
