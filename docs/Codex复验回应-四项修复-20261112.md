## 一、阻塞付款：已出账退款调整被二次乘履约比例（promo.mjs）

- **根因**：调整（=被退项净额×快照履约占比，"商户应付级"冲抵）此前被并入补充单五口径基数 total，再乘履约占比 → 二次乘比例（8192 账单 #39 案例：−6960 进基数×58% → 多付 ¥29.23）。
- **修复**：调整不再进 total。补充单 total = Σ本单结算行净额；`fulfillRaw = round(total×快照履约占比)` 后，未冲抵调整在**履约应付上一对一冲抵**：`amt_fulfill = fulfillRaw + appliedAdj`（appliedAdj = max(adjSum, −fulfillRaw)）；超出本单履约应付的结转余额落新调整行（挂本单、未冲抵，留待下期），绝不把应付出成负数。五口径恒等由 retained 兜底保持。调整标记 applied_settlement_id = 补充单号（对账可溯）。
- **复验对照**：Codex 案例——补充单行净额 12000、调整 −6960 → amt_fulfill = 6960 − 6960 = **0**（同额冲零）✓；已付款后 7900−4582 → **0** ✓；纯负调整无新单 → 本轮跳过、调整保持未冲抵 ✓；重复重算幂等 ✓；五口径/费用/最终应付逐项断言 ✓（test:fix34 已按新口径改写并新增"同额冲零"断言）。
- **连带修正**：结算列表 `adjust_pending` 只统计**未冲抵**调整（applied 的金额已进补充单履约列，不再在原单重复显示）；payable_after_adjust = amt_fulfill + fee_merchant + adjust_pending。
