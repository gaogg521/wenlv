# 第二批补齐：实施与验收

第二批可实施范围完成并验证 ✅。两个小程序＋PC后台，不建设H5；包括第二批前置的自由豆独立域及B05/B06/B07/B08/B13，套餐和部分退款留第三批。

## 实际交付与入口

| 能力 | 入口与行为 |
|---|---|
| 销售授权 | PC「推广服务商 → 产品销售授权」。运营/超管维护人员×产品、生效期、状态、协议依据和约定费率；约定费率＞生效产品覆盖＞档位，12%封顶。新单保存首触推广员/资格/费率/来源快照，后改不改已售。旧通用码保留；已有明确授权记录的组合受其限制。 |
| 产品推广 | 游客「我的 → 推广中心 → 可推广产品与素材」。产品、实时早鸟价、团期余位；专属场景记录、分享卡片及文案。冷启动先解析产品再记录有效来源；保留首触唯一，来源不等于最终计佣归属。微信配置就绪后支持真码海报/相册保存；未配置不生成假图。跨产品浏览不携带错误的产品专属来源阻断普通购买。 |
| 佣金/提现 | 推广中心「逐笔佣金明细」「提现记录与回单」：日期/产品/状态筛选、基数/费率/观察期、占用/可提/冲正、收款尾号及维护说明。本人可申请、撤销待审和重提；PC财务先审批待付款3，再上传真实回单及登记付款。 |
| 合作中心 | 「我的 → 合作中心」切换授权主体；项目/合同/登记投入/当前比例/协议有效期/尾号。分润按日期/产品分页，展示来源结算、基数、应付/已付/待付/冲正；原共创账本及回单同源。受控反馈→PC合伙人中心回复→本人追踪。合作身份不授核销权。 |
| 身份与总览 | 双向微信登录均拒绝多账号/身份冲突，不自动合并历史。商品经营总览增加销售授权和自由豆责任/实付；无套餐数据不虚构。 |
| 官方自由豆 | PC「资金工作台 → 自由豆规则与发放」，超管批准预算，运营/超管配置满减模板和定向批量发放；财务/超管进入「自由豆补贴对账」。游客「我的 → 自由豆」按状态分页，预订页服务端试算并选择一份。 |

## 资金、状态与兼容契约

- 自由豆是官方固定满减权益，无通兑比例/充值/转赠/提现/旅豆兑换。金额存分，0＜减免＜门槛；按实际售价/早鸟价商品额达标，保费不凑门槛。每单一份，与旅豆互斥。
- 199元用满100减50，现金实付149；佣金、成长及原现金分账仍使用真实实付入口，官方50另列责任，不重复当销售额/佣金基数或返豆来源。原固定奖励规则不自行放大或另改。
- 独立`freedom_budget/template/batch/right/event/order/payment`，不写旅豆余额/账本/历史封存。模板只影响未来发放，已发券/已售单保存规则快照；批次幂等号绑定接收人快照，不足预算或用户不合法整批拒绝。
- 发放按券面最大责任预占；锁单不重复扣预算；与名额/建单同事务，失败回滚。支付重复回调只使用一次；取消/超时只释放一次。停发不抹掉已售权益；整批撤销后取消的权益不恢复可用。
- 退款完成才冲正补贴并按原有效期返还原权益，过期不延期，处理中不提前返还；只退实收现金。已付补贴保留历史付款并列待追回，实际追回前继续占预算，避免超承诺。
- 只有有效、服务已完成、用户/商户正常的补贴单可登记真实付款；支持有依据的实际追回/冲正。人工登记不会发起银行转账，也不宣称到账。
- 首版补贴单禁止后台改期调价，提示按原规则退款后重订，避免绕过范围/金额快照。套餐分摊与部分退款必须第三批按B04闭环后再开放。
- 提现旧0待审/1已登记付款/2驳回含义不变，新3为审批通过待付款；旧明确填写真实流水的合并登记保留兼容，新PC流程先审后付。待审/待付均占用并计日限额；冻结、退款冲正后余额不足、重复流水拒绝推进；本人撤销/驳回可重提但保留旧记录。申请保存收款尾号快照，不向小程序返回完整银行资料。
- 本人及主体范围逐次从JWT/经办授权限定；银行回单私有存放，按业务归属鉴权下载。历史共创没有比例快照时明确标注，不倒填当前比例；新生成分润保存比例及规则版本。投入登记不表示应返本金或保障收益。
