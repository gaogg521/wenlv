### 后端常驻（2026-11-04 起，已解决「服务老是断」）

**根因**：本环境按轮次回收进程树——`&`、Bash 后台任务、`Start-Process`、**pm2（连它的 daemon 一起）** 全部活不过一轮。所以任何"在会话里起进程"的方案都会反复断。

**正解**：交给 Windows 计划任务（Task Scheduler 服务拉起，不属任何会话进程树）。

| 项 | 值 |
|---|---|
| 任务名 | `WanderlustAPI-KeepAlive` |
| 触发器 | **登录时**（主）+ **每 4 小时**兜底 |
| 动作 | `powershell.exe -NoProfile -NonInteractive -WindowStyle Hidden -ExecutionPolicy Bypass -File api\daemon\keepalive.ps1` |
| 工作目录 | `wanderlust/api/daemon`（**必须设**，否则默认 `C:\Windows\System32`，任务窗口的标签路径会暴露这一点） |
| 运行身份 | `allenzhao` / Interactive / Limited（S4U 与服务账户均需管理员，当前会话无此权限） |
| 脚本 | `wanderlust/api/daemon/keepalive.ps1`（端口无监听则 `Start-Process node --env-file=.env src/index.mjs`，5 秒后自验 200，结果写日志） |
| 日志 | `wanderlust/api/daemon/keepalive.log`（超 2000 行自动截断） |

#### 为什么曾经每分钟弹黑框（2026-11-04 修）

第一版写成「每 1 分钟」，用户报告屏幕上不断闪出空的 PowerShell 窗口。排查结论：

1. `-WindowStyle Hidden` **本身是有效的**——受控实验（任务跑 `Start-Sleep 12`）测得进程 `MainWindowHandle=0`，PowerShell 自己确实没开窗。
2. 真凶是 **Windows Terminal 1.24**（已安装，Win11 下接管控制台宿主）：`HKCU\Console\%%Startup` 的 `DelegationConsole` 为全零（系统决定），于是每个新控制台进程都会在 Terminal 里**新开一个标签页**，`SW_HIDE` 管不到宿主窗口。
3. 触发频率是放大器：1 分钟一次 = 每分钟一个标签。

**处理**：频率降到「登录时 + 每 4 小时」；VBS 备选方案**已放弃**——`wscript`/`cscript` 属安全策略禁用的 LOLBin，不许用，也不要再试。

**要彻底零窗口只有两条路（均需管理员权限，当前会话没有）**：
- **A. 注册为 Windows 服务**（Session 0 运行，标准做法，可配崩溃自动重启）
- **B. 任务改 S4U / SYSTEM 身份**（非交互会话，`New-ScheduledTaskPrincipal -LogonType S4U`）——试过，`Access is denied`


**常用命令**：
```powershell
# 查状态
Get-ScheduledTask -TaskName 'WanderlustAPI-KeepAlive' | Select-Object TaskName, State
# 重新注册（脚本改动后无需重注册，任务每次调用都会重读脚本）
Register-ScheduledTask ...   # 见 keepalive.ps1 头部注释或 git 历史
# 卸载
Unregister-ScheduledTask -TaskName 'WanderlustAPI-KeepAlive' -Confirm:$false
```

**已实测演练**：手工杀掉全部 `node index.mjs` → 端口不可达 → 自动恢复 200，日志留痕「端口 8080 无监听 → 已拉起，验证 200 OK」。（该次演练在「每 1 分钟」配置下完成，75 秒内恢复；改成 4 小时兜底后，**平时靠登录触发那一次**，兜底只防意外退出。）

**判据**：计划任务拉起的 node 不会被环境清理（**这是关键事实**——18:08 起的进程到 18:24 仍在，说明跨轮次存活成立），所以正常情况一整天不用管。发现服务不通时：
1. 先看 `keepalive.log` 最后一行；
2. 若为空 → 说明还没到兜底时刻，手动 `Start-ScheduledTask -TaskName 'WanderlustAPI-KeepAlive'` 立即触发一次；
3. 若写着「尝试拉起但验证失败」→ 才是真问题（MySQL 没起 / 端口被占），不是守护的锅。

## 五B、双模式质量门禁（真机体验的红线）

**教训来源**：真机上次看到「我的/旅豆」全是"服务不可达"——因为兜底只接了首页/主题游/商城三页，且**只测了模拟器**（模拟器走 127.0.0.1 永远通），没测"后端不可达"这个真机常见状态。

**现在的规矩：每次改前端，两种模式都要跑。**

| 模式 | 命令 | 断言 | 当前结果 |
|---|---|---|---|
| 正常模式（后端可达） | `bash debug-cli.sh` | 16 页逐页 OK + 黄金链路 + 首页真实线路数 | 16/16 + FLOW DONE ✅ |
| 降级模式（后端不可达） | `node api/test/quality-gate.mjs` | 把 apiBase 指向死端口，11 个关键页断言：内容就绪 + 字段完整 + **无 NaN 红线** | 11/11 ✅ |

**降级模式覆盖的 11 页**：首页、主题游、商城、旅豆、我的、我的订单、数字身份、创作中心、推广中心、目的地、FAQ。

**两条硬约束**：
1. `FALLBACK` 演示数据的字段名必须**严格对齐页面渲染字段**（不是随便造几个好看的数字）。踩过两次：ledger 用了 `type/title`（页面要 `direction/biz_type/tx_no/created_at`）→ 流水标题全空、正负号反；orders 用了 `amount`（页面要 `amount_pay`）→ 价格显示 **¥NaN**。
2. 断言不能只查"列表非空"，必须查**每个字段都有内容** + 页面数据序列化后**不含 `NaN`**——否则 NaN 这种缺陷会一路绿灯通过。

**已知环境事实**：本机挂了系统代理，开发者工具与 curl 走代理都到不了 `172.29.128.120:8080`（需 `--noproxy "*"`）；真机走局域网 IP 的前提是**手机与电脑同一 WiFi**，蜂窝网络不可达。所以演示场景优先依赖演示兜底，真实数据等后端上云后自然解决。

| B14 | 计划任务加了 `-WindowStyle Hidden` 仍每分钟弹空窗口 | **Windows Terminal 接管了控制台宿主**（`HKCU\Console\%%Startup` 的 `DelegationConsole` 为全零 = 系统决定 → 用 Terminal），`SW_HIDE` 只隐藏进程窗体，Terminal 仍会开标签页；1 分钟一次的频率把问题放大 | ① 频率降到「登录时 + 每 4 小时」；② 判据别只看 `MainWindowHandle`（Terminal 托管时它为 0，会误判"没窗口"）；③ 想要零窗口只能**以管理员装服务 / 改 S4U 身份**，别在 `wscript`、`cscript` 上打转（安全策略禁用的 LOLBin） |
| B8 | curl / 开发者工具连不上局域网 IP | 本机挂**系统代理** | `curl --noproxy "*"`；真机还需手机与电脑**同一 WiFi** |
| B9 | 手机连不上 8080 | Windows 防火墙 | 管理员执行：`netsh advfirewall firewall add rule name="wanderlust-api-8080" dir=in action=allow protocol=TCP localport=8080` |
| B10 | 换了 JWT_SECRET 后凭据全解不开 | `secrets.mjs` 用它派生凭据主密钥 | 改 `.env` 前先读 `secrets.mjs`；本地保持历史值 |
| B11 | 集成中心显示「● 已配置（生产模式）」，但登录仍走 mock openid | ①库里的凭据是用**另一把主密钥**加密的（换过 JWT_SECRET / SECRETS_KEY，或多个进程环境不同），解不开 → 静默回退 `.env`；②绿标只看“DB 或 .env 有没有值”，**不校验能否解密** | 看启动日志 `[secrets] N 条凭据无法用当前主密钥解密`，或跑 `secretsHealth()`；修复：在集成中心重新「设置」一次（或 `setSecret`）用当前主密钥重加密；判断真假登录：用假 code 打 `/c/auth/login`，返回 **40029 invalid code** = 真实调微信（凭据有效），返回 token = 仍是 mock |
| B12 | 多个 `node src/index.mjs` 实例同时存在 | 反复启动/重试留下游离进程，端口与密钥状态互相干扰 | 只保留一个实例；重启前先 `Get-CimInstance Win32_Process` 清干净 |

### C. 前端渲染层

| # | 症状 | 根因 | 正确做法 |
|---|---|---|---|
| C1 | 某个分包**所有页面**打不开：导航静默超时、console 只有 `Page "…" has not been registered yet`、CLI 无任何报错 | wxml 绑定里的复杂表达式让**整个分包静默编译失败**（已确认：`(x/100).toFixed(2)`、`['…'][idx]`、嵌套三元） | 格式化/映射放 JS 预计算成字段；判据：`__wxAppCode__` 里是否出现 `package-*` 键（`api/test/diag-code.mjs`） |
| C2 | 改完 wxml 仍打不开 | 分包**没有重新编译**（假失败） | 用 `diag-code.mjs` 复核是否已注入，再决定改不改代码 |
| C3 | "全绿"却仍有页面打不开 | 逐页清单手抄漏页（曾只测 7 页/16 页） | 清单必须来自 `app.json` 全量；覆盖率不足的全绿有害 |
| C4 | 真机「我的/旅豆」等页显示"服务不可达" | 兜底只接了首页/主题游/商城 | 全站兜底 + 双模式门禁（§五B） |
| C5 | 演示数据渲染出 `¥NaN`、流水标题全空、正负号反 | 演示字段名与页面渲染字段不一致 | 严格对齐：ledger→`direction/biz_type/tx_no/created_at`；orders→`order_no/amount_pay/days_desc/qty/status_text`；**先看 wxml 再写数据** |
| C6 | 门禁全绿但页面是坏的 | 断言只查"列表非空"，NaN/空字段照样通过 | 断言查**字段完整性** + 页面数据**不得含 NaN** + **截图必须目视复核** |
