# 商户/景区独立 PC 身份与授权核查（V82）

> 状态：**实现完成／自测通过，待 Codex 独立复验**。迁移 V82；专项 `npm run test:partner` 5/5（隔离库 `wanderlust_pi_20261112`、API 18345）。
> 依据：[三端UI会员体系与经营测算-补充验收-20261111.md](三端UI会员体系与经营测算-补充验收-20261111.md) 第3项——"复用已有身份和主体授权，商户和景区的 PC 入口及主体映射需交付实测。"

## 一、核查结论（实施前缺口）

| 主体 | 实施前 | 缺口 |
|---|---|---|
| 商户 | mini-b 商户端（end=m）可核销/看结算；**无 PC 身份** | 无法在 PC 查看本店订单/结算/商品 |
| 景区 | 无任何登录身份；景区算账由平台角色（super/ops/finance/本城 city_partner）代看 | 无法以自己身份查看本景区经营与复盘 |
| 城市合伙人 | 有 PC 身份（scope_city 行级隔离） | 不覆盖"主体方本人"视角 |

## 二、本批实现（复用既有 admin 身份体系，不另造账号系统）

- **V82 迁移**：`admin_user.subject_type/subject_id`（merchant_partner→merchant.id；scenic_partner→scenic_spot.id）。
- **两个新角色**（`modules.mjs`）：
  - `merchant_partner`（商户主体方）：模块 `orders/settlements/products/merchants`；不给 dash（平台聚合）、资金工作台、参数中心、账号管理。
  - `scenic_partner`（景区主体方）：模块 `orders/scenics/settlements/products`；同样不给平台聚合与资金治理。
- **账号创建/改绑**（`admin-accounts.mjs`）：主体方角色必须绑定存在且**正常营业/合作中**的主体（1004 拦截不存在、1001 拦截停用主体）；改绑走既有改角色流程（原因必填入审计、token_epoch+1 全会话失效）。
- **登录令牌**：两条登录路径（密码/MFA）令牌均带 subjectType/subjectId；`requireAdmin` 每请求**从库重读**绑定主体（改绑即生效，夹具令牌自带字段用于测试）。
- **行级隔离落点**（全部实测）：
  | 接口 | merchant_partner | scenic_partner |
  |---|---|---|
  | `GET /admin/orders`（列表） | 只含本店订单 | 只含本景区商品订单 |
  | `GET /admin/orders/search`、按筛选导出 | 同上（orderFiltersOf 统一注入） | 同上 |
  | `GET /admin/orders/:no`（详情） | 他店订单 1003 | 非本景区商品订单 1003 |
  | `GET /admin/settlements`（列表） | 只含本店结算 | 只含本景区关联商户结算（EXISTS tour_product.scenic_id） |
  | `GET /admin/settlements/:id/adjustments` | 他店 1003 | 非关联商户 1003 |
  | `GET /admin/products`（列表） | 只含本店商品 | 只含本景区商品 |
  | 景区算账 `POST /admin/scenics/:id/calculator`（含复盘保存/读取/options） | 只能带本店商户（未带强制本店）；未关联景区 1004 | 只能算本景区，他景区 1004 |
  | 平台模块（资金工作台/参数中心/账号） | 模块未授权 1003 | 同 |
- **PC 页面**：账号管理角色下拉与角色中文名支持两角色；创建/改绑表单出现"绑定主体ID"字段（商户管理/景区资源里的编号）。主体方登录 PC 后首页=订单列表（自身范围），菜单按模块白名单渲染。

## 三、测试证据（test:partner 5/5，单号与账号留档）

1. 账号创建：缺主体 1001、不存在主体 1004、A/B 两主体方创建成功。
2. 真实登录：`/admin/login` 密码登录返回带 subject 的令牌（ver 会话链路）。
3. 商户主体方：订单/结算/商品列表逐行 `merchant_id=本店`；他店订单详情 1003、他店结算调整 1003；资金工作台/参数中心 1003。
4. 景区主体方：本景区算账可算（fingerprint 生成）、他景区 1004；订单只含本景区商品；结算只见关联商户（A店可见、B店不可见）；非关联结算调整 1003。
5. 改绑主体：epoch+1 旧令牌 1002 失效；重登后按新主体（B店）隔离。

## 四、边界与下一步（单列）

- **未覆盖面（单列）**：商户主体方的商品**写**操作（建品/改价/团期）暂按平台既有角色守卫（仅 super/ops）——主体方默认只读；如需开放本店商品自维护，需另行评审后放开（路由级 merchant 校验）。
- 城市合伙人保持原有城市级隔离不变；两角色叠加 city scope 的场景不支持（互斥设计，创建时不可同时绑定城市）。
