### 1.3 景区主体(scenic_partner)

- 现状唯一"写"为经营动作(跟进申请/测算快照),无商品写权限(`POST /admin/products` roles 不含 scenic_partner),无景区资料写入口(实体 schema roles 仅 super/ops)。
- 归属证据:`tour_product.scenic_id`(V22)+`tour_product.license_type`(V1,1 自营/2 合作代销/3 单票代理);**无独立商户↔景区绑定表**,partner-dash 口径一律 `scenic_id=subjectId`。
- 方案冲突取舍:现有模型无法无歧义表达"景区自营商品"归属 → 按方案**首版只开放景区资料审批**;另在 V95 增加 `scenic_spot.selfrun_merchant_id`(经超管确认的自营经营主体)字段,后续可无歧义开放自营商品写入(本次仍不放开,见交验单)。

## 2. 实际字段(实体 schema 摘录,entity-schema.mjs)

- product(:34-117):title/subtitle/cat/city_code/days_desc/price_from(元展示、分存储)/bean_gift/rich_desc{intro,includes,excludes,highlights,video}/itinerary(repeat)/images(gallery)/meeting_point/safety_note/merchant_id/supplier_id/scenic_id 等;validate 含商户已审核、P-06 城市一致性、赠豆比例上限。
- session(:120-159):depart_date/status(1 报名中 2 已成团 3 已截止 4 已取消)/quota/min_go/price_adult/early_price/early_days/sign_deadline(profile)/gather_time/end_time/leader/vehicle/note/internal_note;validate:早鸟<现价、名额≥已报名、新建日期≥今天。
- merchant(:162-225):品牌与门店(name/short_name/kind/tags/logo/storefront/intro)/营业信息(address/geo/service_phone/business_hours/capacity/facilities)/资质证照(biz_license/legal_person/license_img/permits)/结算账户(wxpay_sub_mchid/settle_cycle/account_no[sensitive] 等)/联系人与合作(contacts/contract_no/remark)。
- scenic(:228-268):基本信息(name/alias/level/cover/gallery/intro)/开放与票务(address/geo/open_hours/tickets[含 settle 结算价]/ticket_interface/traffic)/合作条款(coop_mode/profit_terms/contract/contact/remark)。

主体可提交字段白名单与平台专管字段的完整对照见《主体资源审批-权限与字段对照表-20261120.md》。

## 3. 正式写服务与版本簿

- 统一入口:entity-schema.save(kind,input,ctx,tx)(:838-937)——乐观锁(expectedVersion,product/merchant 用 updated_version,session 用 version)、逐字段规范化、敏感词拦截、审计打码、master_data_version 版本簿(kind∈product/merchant/session,只增不改)。
- 直写服务(非 entity):`PUT /admin/products/:id/stock`(库存行 booked+available,previous 幂等校验)、`POST /m/supply/:sid`(X-03 乐观锁+recordVersion)、`POST /admin/products/:id/status`(上架前置完整性校验+attestProductChange 存证)。
- 订单价格快照:orders 表创建时锁定价格(expectedGoodsFen 保护),审批后新单按新价、原单保持原价——现模型已满足 AC03 后半句,无需改订单。
- 版本簿:`master_data_version`(V56)+ recordVersion(master-version.mjs)。

## 4. 可用审批与通知基础设施

- 审批范例:笔记人工审核(admin-ops.mjs:228 verdict 状态机 0/1→2/3)、约稿投稿(admin.mjs:1705+content_task_review)、商户进件(merchant.status 0→1/2)、景区跟进(scenic_followup submitted→approved/rejected→recorded,V83)、审核队列聚合+认领(review_claim,V49/V52 唯一键防重复)。
- **没有**通用的"主体资源审批"状态机 → 本次新建(申请表+状态机+正式写服务)。
- 通知:订阅消息 sendScene/notifyMerchant(notify.mjs,V91 notify_log,V93 商户偏好)+ 支付回调 fire-and-forget;**没有站内收件箱表**、顶栏无未读、首页无待审数 → 本次新建 platform_inbox + 顶栏铃铛 + insights 扩展。

## 5. 现有运营权限

- 模块:modules.mjs 50 模块,V54 角色矩阵+V55 账号三态(admin_role_module/admin_user_module),requireModule 网关闸(ROUTE_MODULES 约 230 条映射),城市账号叠加 CITY_DENY_MODULES。
- 动作:ADMIN_ACTIONS(admin-capabilities.mjs)静态角色映射,requireAdmin(req,action) 校验;**无按员工的三态动作授权表** → 本次新建 admin_user_action(允许/收回,超管授予),审批权 subject.approve 基线仅 super,运营按员工单独授予。
- 商户端岗位:merchant_staff.role(1 核销员 2 店长 3 老板),staff-role.mjs 每请求实时覆写(30s 缓存+写时失效);V93 三态偏好 NULL=按岗位默认。
- 会话版本:admin_user.token_epoch(停用/改角色/改城市/重置密码 +1,旧会话 1002);商户端无权限版本 → 本次新建 subject_perm_version 下发版本 + /m/perm/snapshot 快照同步。

## 7. 历史订单快照与游客读数

- 订单:orders.merchant_id、contribution_scenic_id(order.mjs:113-114),价格与结算走既有快照;审批不触碰订单表。
- 游客读数:`/c/tours`、`/c/tours/:id` 读 tour_product/tour_session 正式行;申请(草稿/待审)不写正式表 → 审批前游客端天然不可见(AC02 前半句由模型保证,测试断言验证)。

## 8. 与本方案冲突的取舍清单(交验单"取舍"栏)

1. **景区自营商品写入**:模型缺无歧义归属 → 首版不开放,只交付景区资料审批(V95 预埋 selfrun_merchant_id 判定字段)。
2. **商户小程序新增商品**:mini-b 现无商品档案编辑页;本次交付供给变更(价/库存名额/停售/恢复/早鸟)申请+跨端进度查询,商品新增以 PC 为主体端入口(方案 AC02 由 PC 端验证),小程序商品新增表单列入后续批次。
3. **mini-b 即时改价变申请制**:原 M 系列直写入口全部改为"提交审核",交互保留二次确认;确认后即时生效的旧行为不再存在(方案§5 明确收口)。
4. **ops 审批权**:沿用 ops 角色不新建角色;审批权=新动作 subject.approve,基线仅 super,由超管按员工授予(admin_user_action)。
5. **PC 快速改价**:PC 无独立快速改价页(改价走团期编辑器),团期级改价收口在申请制内,页内交互不变。
