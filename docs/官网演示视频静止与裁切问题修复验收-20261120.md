# 官网双端演示视频「静止/顶部被裁」问题修复验收（2026-11-20）

## 一、用户反馈
1. 视频没动，看起来就是一张静态图片。
2. 小程序画面没有上面部分，只有下面部分（顶部「世界就是我的游乐场」标题区消失）。

## 二、根因（两个独立问题）

### 问题 1：视频静止不动 —— WebM(VP9) 解码卡死
- 生产浏览器实测：`<video>` 处于 `paused:false` 状态，但 `currentTime` 在 2 秒内始终为 0，画面不前进。
- 对照实验（同一 Chrome，直接加载两个源）：
  - `mini-a-walk.webm`（VP9）：`t1=0 → t2=0`，`paused:true` —— **解码卡死**。
  - `mini-a-walk.mp4`（H.264）：`t1=1.97 → t2=3.98`，`paused:false` —— 正常。
- 页面 `<source>` 顺序是 WebM 在前，浏览器认定支持 VP9 就选它，但实际解码卡死 → 用户看到静止画面。
- **修复**：把 MP4 放第一位（H.264 兼容性最好），WebM 降为兜底。

### 问题 2：顶部被裁 —— 录屏开头页面未归零 + 静止预热帧
- 旧视频第 0~3 秒画面完全静止，且第一帧就停在首页中部（「亲子时光/好友出游」卡片），顶部 hero 区从未被录进去。
- 两个叠加原因：
  1. `switchTab` 到首页时会**沿用上一次的滚动位置**，脚本没有先 `pageScrollTo(0)`，导致录制从首页中部开始。
  2. Python 录屏进程比 automator 时间线早启动约 3.8 秒（等待连接），那段时间抓的是「录制前页面停留位置」，形成开头静止段。
- poster 恰好取第 20 帧（约 1 秒处，中部画面），用户第一眼就是「静态 + 只有下半部分」。
- **修复**：重写 `record-mini-walk.mjs` —— ①连接后先把首页切到并 `pageScrollTo(0)`，再启动录屏；②每个页面进入后立即归零；③开头 0.6 秒即开始平滑滚动。poster 改取第 0 帧（完整首页顶部）。

## 五、经验（写入踩坑档案）
- WebM/VP9 在本环境（Chrome headless + 官网 HTTPS）会 `paused:false` 但 `currentTime` 卡 0；**演示视频一律 MP4(H.264) 优先**，WebM 仅作兜底。
- automator `switchTab` 不重置滚动位置；录制前必须显式 `pageScrollTo(0)`。
- 录屏进程要在页面就位后才启动，否则开头是静止的「录制前画面」。
- 验收不能只看 `paused`/`readyState`——必须验证 `currentTime` 随时间**实际前进**，否则会漏掉"假播放"。
