## M-01 改价权限：老板与店长一致可用，权限变化即时生效（P0）

**做了什么**
1. **角色以库为准**：新建 `api/src/infra/staff-role.mjs`——`staffRoleOf(uid, merchantId)` 查 `merchant_staff` 当前 role/status，进程内缓存 TTL 30 秒；`routes.mjs` 的 `/m/*` 中间件改为每次请求取实时角色并**覆写 `u.role`**（handler 内所有 role 门槛自动实时化）。删掉旧逻辑里「角色变更踢下线（1002 角色已变更，请重新登录）」——现在改岗后同一 token 立即按新角色行事。缓存有**显式失效**：`POST /m/staff/:id`（老板改岗/停用）成功即 `invalidateStaffRole`，所以「立即」不是 30 秒后。
2. **撤销「仅老板可调价」旧闸**：`routes.mjs` 原 78 行 `POST /m/supply/:sid && action==='price' && staff.role < 3 → 1003` 是 2026-10-26 引入的旧限制（git 追溯提交 e75eeb1），与负责人 2026-11-19 原话「老板和店长都要能改价格」冲突，已删除。现在五个入口的门槛统一为 role>=2（中间件 manager 正则 + handler 内 role<2 校验），核销员 role=1 全部 1003。
3. **改价交互**：mini-b 库存页 `changePrice` 输入限两位小数（正则 `^\d+(\.\d{1,2})?$`，元→分 `Math.round`），服务端拒非整数分（`价格必须为正整数分`）；成功提示带旧→新（「已改价 ¥238.00→¥198.00」）；冲突 2002 文案保持明确（「该团期价格刚被其他端修改…」）。±30% 二次确认见 M-12。

**断言**（`api/test/merchant-notify-round.mjs`，隔离库自建商户+商品+团期+三岗位夹具，严格断言）：
- 核销员(role1) × {单个改价、批量改价、早鸟、调名额、停售、恢复} 六入口全部 1003；
- 店长(role2) × 全部通过；老板(role3) × 全部通过；
- 价格非整数分 → 1001；
- **改岗实时生效**：老板把店长降为核销员 → 同一 token 改价立即 1003；升回店长 → 同一 token 立即通过；停用 → 同一 token 工作台立即 1003；启用恢复。全程不重新登录。

## M-02 到单提醒默认开启（P0，三层）

**做了什么**
1. **员工级偏好（迁移 V93，只增不改）**：`merchant_staff` 加 `notify_new_order / notify_refund_apply / notify_settlement_pending`（**三态：NULL=按岗位默认（老板/店长开、核销员关，发送与读取时解析）、0=明确关、1=明确开**）+ `notify_onboarded` + `created_at`；迁移内回填：现有员工 role>=2 三项显式置 1、核销员置 0。三态设计的用意：任何时点 SQL 直插的员工行（种子/夹具/批量导入）天然带岗位默认，不会因「列默认 0」漏发。接口 `GET/POST /m/notify/prefs`（本人可改，核销员也能自行打开；GET 返回按岗位解析后的生效值）。`notifyMerchant`（domain/notify.mjs）发送前按偏好过滤（`(pref=1) OR (pref IS NULL AND role>=2)`）——**关掉某一项后不再产生任何发送记录**（含 skipped）。
2. **「我的」页开关 + 三态**：到单提醒行改为展开面板：三个偏好开关（即改即存）+ 状态行，`wx.getSetting({withSubscriptions:true})` 判定：`已开启（微信订阅正常）/ 授权额度不足，点此补订阅（按钮→手势内 requestSubscribeMessage）/ 微信通知总开关已关，去设置（按钮→wx.openSetting）`，模板未配置时如实显示「提醒通道未接入（联系平台配置模板）」。
3. **首次引导 + 工作台兜底**：老板/店长首次进工作台弹一次引导（`notify_onboarded` 落库，可跳过，跳过/去设置后不再弹）；工作台 `onShow` 起 **30 秒轮询 `GET /m/notify/poll?after=<lastId>`**（返回 latestId/newPaid/pendingVerify；首轮只校准基线不把历史单当新单），有新支付订单→顶部提示条（可点进订单页/可忽略）+ 订单 tab 红点（custom-tab-bar 新增 setDot/自绘 `tb-dot`）+ `wx.vibrateShort`；`onHide/onUnload` 停止轮询；工作台支持下拉刷新（M-05 一并）。
4. **不假装**：微信订阅是一次性授权，代码只在手势内请求、额度用尽引导补订阅；真实订阅模板 ID 仍是外部条件（X-05），MOCK 下验证落 `notify_log` + 偏好过滤 + 应用内提示（见断言与截图）。

**断言**：默认偏好老板/店长三项开、核销员三项关；核销员可自行开/关；`notifyMerchant` 发送对象=偏好为开的在职员工（关闭后 sent 从 2→1，notify_log 只剩 role3）；`/m/notify/poll` 店长返回 latestId/newPaid/pendingVerify、核销员不返回 newPaid。
