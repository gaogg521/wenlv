# 旅行笔记举报与下架申诉（2026-11-03）

## 已实现闭环

1. 读者在笔记详情填写具体原因，提交举报；同一读者同一笔记只保留一条举报，重复提交返回已有记录，不能举报自己作品。
2. 后台「内容数据 → 举报与申诉」查看原文、举报原因，填写处理原因，判不成立或下架；下架同时处理同笔记其他待审举报。也可从原内容审核页主动下架。
3. 下架立即从公开详情撤下；作者在创作中心看到下架原因并提交一次申诉；非作者不能代提交。
4. 后台查看当前内容与下架快照，填写复核原因，恢复展示或维持下架。作者可见结果；原举报者的举报记录也反映内容已复核恢复。
5. 每次下架独立编号，申诉只针对该次下架；旧申诉不能恢复后来重新下架的内容。重复并发提交、重复判定由唯一索引与行锁保护。所有人工处理审计留痕。

原因 4—300 字，使用现有小程序用语检查；所有展示按纯文本处理，正文复用清洗/审核视图。不对作者下发举报者身份，不对读者下发作者申诉理由或后台操作人。

本轮对象是旅行笔记。线路评价原有展示/隐藏流程保持原状；没有将笔记申诉套入资金奖惩，也没有自动撤销既有约稿奖励。

- V36 建举报、下架快照、申诉及当前下架关联；V37 为旧 status=4 笔记保留正文并明确原原因缺失，使存量作品也能申诉。状态保持下架，不自动恢复。
- 后台 super/ops/review/city_partner 可处理；finance/risk/readonly 无入口且 API 拒绝。
- scopeCity 同时限制提交/下架时城市和笔记当前关联线路城市，覆盖队列、详情、处理及复核。未关联、关联线路删除或跨城变更后的旧记录只留平台处理；不能借旧审核接口绕过城市限制。
- 复用小程序 `package-content/pages/note` 与 `create`，无新增 app.json 页面；MINI_MAP 已补登记。后台新脚本及 NAV/renderer/description 已登记。
