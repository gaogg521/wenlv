### 2. 生成独立发布包（PowerShell）

以下从指定Git提交提取已提交源码，确保包与sourceCommit一致；不要直接打包脏工作区。`release`必须是`YYYYMMDD-HHMMSS-提交短号`。官网无需npm构建。

```powershell
$release = (Get-Date -Format 'yyyyMMdd-HHmmss') + '-' + $sourceCommit.Substring(0,7)
$stage = Join-Path $env:TEMP ('wenlv-site-' + $release)
New-Item -ItemType Directory -Path $stage | Out-Null
$sourceArchive = Join-Path $stage 'source.tar'
git archive --format=tar --output=$sourceArchive $sourceCommit -- 招商宣传站/site 招商宣传站/ops
if ($LASTEXITCODE -ne 0) { throw 'git archive failed' }
tar -xf $sourceArchive -C $stage
Copy-Item -Recurse (Join-Path $stage '招商宣传站/site') (Join-Path $stage 'site')
Copy-Item -Recurse (Join-Path $stage '招商宣传站/ops') (Join-Path $stage 'ops')
$siteRoot = Join-Path $stage 'site'
$hashes = @{}
Get-ChildItem $siteRoot -File -Recurse | ForEach-Object {
  $key = $_.FullName.Substring($siteRoot.Length + 1).Replace('\','/')
  $hashes[$key] = (Get-FileHash $_.FullName -Algorithm SHA256).Hash.ToLower()
}
@{release=$release;commit=$sourceCommit;files=$hashes} | ConvertTo-Json -Depth 4 |
  Set-Content (Join-Path $siteRoot 'version.json') -Encoding utf8
$archive = Join-Path $env:TEMP ($release + '.tar.gz')
tar -czf $archive -C $stage site ops
if ($LASTEXITCODE -ne 0) { throw 'tar failed' }
$sha = (Get-FileHash $archive -Algorithm SHA256).Hash.ToLower()
```

### 3. 备份、上传与原子发布

现有服务器上有只读快照工具 `/opt/wanderlust-site/immersive-snapshot.py`：读取112张业务表行数、四份原配置摘要和API/MySQL容器ID，不输出凭据；依赖现有API容器的mysql2以及DB环境。发布前后使用同一工具比对；若工具缺失或环境变更，先恢复同等只读核验，不能直接跳过数据保持检查。

```powershell
ssh onework-62 'python3 /opt/wanderlust-site/immersive-snapshot.py before'
if ($LASTEXITCODE -ne 0) { throw 'preflight failed' }
ssh onework-62 "tar -czf /opt/wanderlust-site/backups/site-before-$release.tar.gz -C /opt/wanderlust-site/current ."
if ($LASTEXITCODE -ne 0) { throw 'backup failed' }
scp $archive "onework-62:/opt/wanderlust-site/$release.tar.gz"
if ($LASTEXITCODE -ne 0) { throw 'upload failed' }
# 脚本来自本轮指定提交；确保LF换行后上传。
$publishPath = Join-Path $stage 'ops/publish.sh'
$scriptText = [IO.File]::ReadAllText($publishPath).Replace("`r`n","`n")
[IO.File]::WriteAllText($publishPath,$scriptText,[Text.UTF8Encoding]::new($false))
scp $publishPath onework-62:/opt/wanderlust-site/publish-pending.sh
if ($LASTEXITCODE -ne 0) { throw 'script upload failed' }
ssh onework-62 "bash /opt/wanderlust-site/publish-pending.sh $release /opt/wanderlust-site/$release.tar.gz $sha"
if ($LASTEXITCODE -ne 0) { throw 'publish failed: inspect rollback output' }
ssh onework-62 'python3 /opt/wanderlust-site/immersive-snapshot.py after'
if ($LASTEXITCODE -ne 0) { throw 'postflight differs: investigate before delivery' }
ssh onework-62 "cp /opt/wanderlust-site/immersive-before.json /opt/wanderlust-site/backups/$release/data-config-before.json"
ssh onework-62 "cp /opt/wanderlust-site/immersive-after.json /opt/wanderlust-site/backups/$release/data-config-after.json"
```

脚本校验SHA256、备份Nginx及原链接、解包、原子切换current、`nginx -t`和平滑reload；失败自动恢复原站配置和链接。只发布官网，不执行docker compose、不迁移或灌写业务库、不覆盖其他vhost。完整旧站包不包含业务数据库，因为本流程不修改业务数据库。

### 5. 回滚（在SSH Bash执行）

`release`填本次需要撤回的发布编号，从它的备份读上一版；不能把整个nginx备份解压覆盖到同机其他站点。

```bash
set -euo pipefail
release=20261119-200042-521a7d6
backup="/opt/wanderlust-site/backups/$release"
previous=$(cat "$backup/previous-release.txt")
[[ "$previous" == /opt/wanderlust-site/releases/*/site && -s "$previous/index.html" ]]
cp -a "$backup/site-before.conf" /etc/nginx/conf.d/ziyou.1work.vip.conf
ln -sfn "$previous" /opt/wanderlust-site/rollback-link
mv -Tf /opt/wanderlust-site/rollback-link /opt/wanderlust-site/current
nginx -t
nginx -s reload
curl --fail --silent --show-error https://ziyou.1work.vip/version.json
```

回滚后同样检查公网浏览器、API和数据配置保持结果。若遇服务错误，先看`nginx -t`及`/var/log/nginx/error.log`，不要通过重建三端服务来修官网静态发布问题。

## 回滚操作

首次上线若需撤下官网，仅恢复本次站点配置与 current 链接，不能把整份 nginx 备份覆盖回去影响其他服务。首次版本的 previous-release 为空，可移除 `/etc/nginx/conf.d/ziyou.1work.vip.conf` 后执行 `nginx -t && nginx -s reload`；证书和发布目录保留以便重上。

后续回滚到已验收版本：将 `/opt/wanderlust-site/current` 原子指向上面的发布 site 目录，使用对应 release 的 `ops/ziyou.1work.vip.conf`，通过 `nginx -t` 后重载。原 API、MySQL、数据卷与配置不参与官网回滚。
