# 商户工作台重构与导航验收（2026-11-08）

## 改价权限澄清

老板和平台运营者都需要改价，这本身不是bug。老板在商户端调整本店团期价格；平台运营者在运营后台维护商品与团期价格，两条路径保留。商户接口原有 role>=2（店长及老板）和本店归属校验未改变，运营后台实体原有 super/ops 权限未改变。本批没有创建账号、扩大权限或改价演示商品。

上批所称问题只指“前端把店长入口藏掉、与现有后端授权不一致”，不能解读为取消老板或平台运营的改价能力。

## 新首页与导航

- 首页改为门店信息、今日经营摘要、扫码核销、四项常用服务、接待提醒、可展开公告、七日订单与评价。金额和订单全部取本店接口，没有编造经营数据，不用动效大按钮挤占首屏。
- 顶部导航适配状态栏和微信胶囊，订单/库存/我的左上角明确回工作台；详情与其他二级页返回上一页，直接打开或返回失败时回工作台。
- 修复自定义底部导航未同步角色及选中状态：店长/老板有工作台、订单、库存、我的；核销员只显示工作台、我的。绑定登录后也同步导航。
- 未登录或未绑定时显示绑定指引，清除上一门店的经营数据；数据失败有重试，公告默认收起，避免挤掉主要操作。
- 现有九页均接入共用导航组件，无新增业务页面；不改变后台、游客端、库存、结算和核销业务规则。

## 验证与边界

npm test退出0，独立 npm run test:merchant-navigation 退出0（tab返回、详情返回失败兜底、角色导航切换及退出清除旧数据）。商户端全部WXML经官方编译器通过。

模拟器实际点击四项服务并返回通过；订单详情返回订单列表通过；直接进入核销/荣誉/我的后回工作台通过。店长四项服务与核销员两项服务显示核对通过，底部导航角色同步通过；核销员显示测试是前端角色切换检查，不冒充新建核销员账号的后台权限验收。原有后端权限未改。

当前接口为8080演示，使用已有 mock-chenjie 店长会话，仅GET业务数据；无下单、改价、核销、支付或通知发送。商户端临时副本借游客AppID启动开发者工具，仓库商户AppID与正式域名未改；不是商户真实AppID/真机验收。
