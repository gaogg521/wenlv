# 「向往的自由」PPT 方案

> 这不是功能清单，是一份"如果让我来做这套 PPT，我会怎么做"的完整方案：先定主张和论证，再排页、配图、写口径。
> 论证全部取自你们自己的《市场洞察五看》《项目总方案》《Web3 对外表述口径》，数字和说法与它们一致；产品证据取自 2026-11-08 的演示库实拍。
> 三端功能和截图的详细对照在 [附录A-三端能力与截图索引.md](附录A-三端能力与截图索引.md)。

## 0. 先定三件事

**① 这份 PPT 对谁讲、要什么。**
主版本讲给**投资人**，目的是"相信这套打法 + 愿意出第一个城市的现金垫"。同一个骨架，抽掉财务页、换成景区收益页，就是给**景区 / 政府**的 BD 版。我建议先做主版本，BD 版是它的子集。

**② 一句话主张（封面和结尾都用它）。**

> 传统旅游 App 卖的是一个点——一张票、一间房。
> 我们卖的是一条能被定价、被核销、被分账的**路线场景**；
> 让这条路线里的每一方都敢参与的，是一套谁也改不了的**可信凭证**。

**③ 叙事主线只走五步，不多不少。**

| 步 | 要回答的问题 | 一句话 |
|---|---|---|
| 1 | 钱漏在哪 | 游客一次出游花 966 元，景区只收到 73.8 元，892 元漏在围墙之外 |
| 2 | 我们换了什么玩法 | 把"一个点"换成"一条路线场景"，把漏掉的钱串回来 |
| 3 | 为什么必须是可信凭证 | 路线是一单多方，没有谁也改不了的凭证，就没有人敢分账 |
| 4 | 凭什么是我们 | 抄得走剧本，抄不走本地履约网络和分账规则 |
| 5 | 怎么走、要什么 | 朱家角样板 → 三年 8–10 城，第一年只考核一件事 |

## 1. 项目价值：三层，从小到大

| 对谁 | 价值 | 证据 |
|---|---|---|
| **游客** | 不用自己拼攻略：一个订单买到"一段有人带的路线"，到了就能玩，玩完有记录、有旅豆、有徽章 | 线路详情含行程节点、集合点、合作景区和履约商户；动态核销码；勋章墙 |
| **景区 / 商户** | 以前只能卖一张票，现在能接一整条路线的客人，并且多一个货架（文创、旅拍），账按时、清楚地结 | 商户端：核销、订单、库存、周结算、经营等级与徽章；二销环比 +18%（演示商户洞察） |
| **行业** | 把"漏在景区外的钱"重新组织回场景里；用凭证把多方分账从"手工账、靠信任"变成"自动账、可复核" | 966 → 73.8 元；A 级景区 16,994 个、人均每人次仅 73.8 元 |

**要点**：价值不要从"我们有个小程序"讲起，要从"这 892 元谁来串"讲起。

## 2. 不同的玩法：从"单点"到"路线场景"

这是整套 PPT 的核心页，建议用一张左右对比图。

| 维度 | 传统旅游 App（OTA） | 向往的自由 |
|---|---|---|
| 卖什么 | 门票、酒店等标品，一个点 | 路线场景：一类人群 + 一段动线 + 一组商户 + 一套分账 |
| 产品单元 | SKU（一张票、一间房） | 场景模板（换城市换内容，不换规则） |
| 谁履约 | 平台不碰履约 | 平台组织、商户履约、全程核销留痕 |
| 钱怎么来 | 抽佣 5–20% | 一单拆成五口径分账：履约 58%、合伙人 8%、平台服务费 12%、留存毛利 17%、权益预算 5% |
| 一单涉及几方 | 一买一卖 | 景区、酒店、餐饮、地接、合伙人、创作者同在一单里 |
| 凭证是什么 | 一张电子票，用完即废 | 履约凭证：核销了才结算，核销记录进账本，成就沉淀成徽章和旅豆 |
| 复购靠什么 | 补贴、比价 | 旅豆（下次最多抵一单的 10%）、徽章（集卡收集欲）、新场景 |
| 留下什么数据 | 一次交易 | 一个人的旅行履历、一家商户的经营信用 |
| 对景区意味着 | 多一个销售渠道 | 把围墙外的住、吃、玩串回来，多一个能结算的货架 |

**怎么讲清"路线场景"**：用朱家角「江南谜案」当例子，一页讲完——

> 09:30 集合出发 → 10:00 主题走读 → 12:00 本地午餐 → 14:00 手作体验 → 16:00 返程。
> 游客只下一个订单；景区、民宿、餐饮、手作商户各自核销自己那一段；每一段核销都对应一份分账。

配图：`游客端/13-线路详情-头图与团期` `14-线路详情-行程安排`（合作景区和履约商户卡）。**注意** `15` 那张商户卡的营业时间现在显示"undefined"，别用。

**口径提醒**：别说"颠覆行业"。你们自己的市场洞察写得很清楚——"我们要做的不是新品类，是存量景区的变现效率"。更稳、更有力的说法是"重构一单的结构"：从卖点，到卖场景。

## 3. 为什么必须基于可信凭证

这一页要回答投资人最容易问的"你为什么不直接做个小程序卖票？"。我会用四层逻辑，每层一句话加一个产品证据。

| 层 | 逻辑 | 产品里怎么体现 |
|---|---|---|
| **① 路线是一单多方，要有对得上的履约证据** | 一个订单要在多个商户、多个时间点履约。谁做了、做了没有，不能靠口头 | 动态核销码（60 秒刷新、HMAC 防伪）、暗号核销、离线核销冲突处理 |
| **② 分账要让各方都信，才会把客人交给平台** | 景区和商户愿意接 58% 的履约款，前提是"这笔账谁也改不了" | 五口径恒等分账；订单、核销、结算每一步生成存证事件，按批次锚定到联盟链；链上只放哈希指纹，数据在自己的库里；任何人可用公开复核页验证一单 |
| **③ 复购和留存要有"真实成就"的载体** | 旅豆和徽章记录的是真实的旅行与消费，不是炒作 | 旅豆履约后到账、T+7 才解冻防退款套利；勋章墙记录签到、打卡、通关；商户有"经营荣誉 / 可信勋章" |
| **④ 政策与合规本身就是壁垒** | 2025 年两项国标只允许实名用户之间无偿或小额有限转赠、禁止竞价；"十五五"规划明确鼓励文旅门票数字凭证和会员数字权益；数字藏品平台从 3000+ 家出清到不足 500 家 | 旅豆不能充值、不能提现、不能交易，12 个月过期，不对应股权或 Token——死的是"藏品"，活的是"凭证" |

**一句话收口**：凭证不是为了"上链"而上链，是为了让一条多方参与的路线**能结算、能复核、能复购、能合规**。

**证据（演示库 2026-11-08 实拍）**：存证事件 918 条，已锚定 909 条（99%），锚定批次 14/14，区块高度 #14；凭证签发 248、到店核销 181、旅豆发放 121；累计发放旅豆 38,773；已发放勋章 36 枚。配图用后台 `23-链路总览` `24-存证中心`，以及 `可信存证样张/` 里的订单存证证明、账本封存证明、公开复核页。

**必须讲清的三句**（来自你们的口径指南，被问到就这么答）：
1. "不发币。我们发的是绑定实体消费的权益凭证，不能充值、不能提现、不能交易。"
2. "资金不落我们账户，走微信收付通分账；每一笔分账都有存证。"
3. "链上只记事实指纹，业务数据在我们自己的库里，不对应股权，不对应收益。"

## 4. 解决的行业问题

| # | 行业问题 | 证据 | 我们的解法 | 产品里看得见的地方 |
|---|---|---|---|---|
| 1 | **景区的钱漏在围墙外** | 游客一次出游 966 元，景区人均每人次 73.8 元，92.4% 漏在住、吃、行、购 | 路线场景把住一晚、吃一顿、玩一场串成可定价的产品 | 游客端线路详情、确认订单 |
| 2 | **内容赚钱，运营赔钱** | 剧本杀实体 186 亿元，但门店年闭店率约 30%；200+ 景区自建产品，缺运营、缺结算、缺复购 | 不做内容供应商，做运营与结算层；内容外采，模板复制 | 小程序装修与映射、商品与团期 |
| 3 | **多方分账靠手工，错一笔就吵一架** | 商户多、口径多、周期长，手工账必错（市场洞察判断 10） | 五口径恒等、自动结算、日终三方对账、商户在小程序确认或发起异议 | 商户端结算、后台结算与资金工作台 |
| 4 | **体验消费客单下行，复购弱** | 出游人次 +16.2% 快于花费 +9.5%，行业在用人数换增长 | 体验溢价定价；旅豆三层闭环把一次消费变成下次的理由 | 游客端旅豆页、勋章墙 |
| 5 | **本地供给散、导游和内容人变现难** | 导游靠购物提成、淡季失业，内容发出去不直接变现 | 推广服务商和创作者只对真实成交按合同计酬，不按层级、不按人头 | 推广中心、创作中心、后台合伙人与创作者池 |
| 6 | **数字凭证行业出清，合规成本抬高** | 数字藏品平台 3000+ → 不足 500；成交额缩水约 70–80% | 绑定实体消费的凭证，按国标形态设计，合规做成准入壁垒 | 存证中心、数字身份、旅豆发行台账 |

## 5. 我们的优势与突出点

**先说清我们不靠什么**（市场洞察原话，也是最稳的讲法）：不靠内容（可抄性极高，AI 让生成成本归零）、不靠技术（有钱就能买）、不靠流量（OTA 的主场）。

**我们靠的控制点**：**本地履约网络 + 分账结算规则**，凭证是它的加固件——要让分账"谁也改不了"。三年后买家买的是这张网络，不是剧本库。

**突出点，按讲的顺序排：**

1. **一单拆五口径，恒等到分**：订单额 = 履约 + 合伙人 + 服务费 + 留存毛利 + 权益预算，协议调价会全链重算。景区手工做不了。
2. **履约即结算、结算即凭证**：核销一次，订单、账本、分账、存证四处同时更新，同一个事务，不是靠对账去追。
3. **一个身份、一本账、一套订单**：游客端、商户端、后台读写同一份数据，没有"商户端一份、后台一份"。
4. **旅豆三层闭环**：对游客是复购钩子，对商家是第二个货架，对创作者是变现出口；兑换锚固定 100 豆 ≈ ¥10，不浮动、不承诺升值。
5. **可复制的是模板**：八类场景（沉浸叙事、社交聚会、单身社交、身心疗愈、运动竞技、亲子自然、研学党建、跨境文化），换城市只换在地内容和商户名单。
6. **后台真能管事**：50 个模块、9 种角色、参数中心（数字全可配、代码零硬编码）、公开复核页、全程审计。

**不要往"优势"里放的话**：AI 生成内容、"Web3"、"去中心化"、"早期参与更值钱"。口径指南里列了十句永远不要说的话，PPT 里一句也别出现。

## 7. 现有 v4 稿（26 页）需要改的地方

我读了 `ppt-work/Wanderlust-商业宣讲-v4.pptx` 的全部文字。骨架（痛点、解决方案、商业模式、壁垒、落地、融资、退出）是对的，但对照你这次提的三个问题，缺三块，另有三处要核实：

**缺的三块**
1. **没有"单点 vs 路线场景"的对比页**。现在只在第 5 页一句话提到"主题场景 = 一类人群 + 一段动线……"，没有把传统 App 的做法摆出来对比。→ 新增第 5 页。
2. **没有回答"为什么必须是可信凭证"**。第 8、16 页讲了"链上记什么"，但没讲"为什么一条多方路线非要凭证不可"。→ 新增第 8 页。
3. **产品只用 3 张后台截图和少量游客端图**，游客和商户的真实体验没展示出来。→ 第 6、9、11、12 页补图。

**要核实的四处**
1. **第 21 页"后台真的在跑，1482 笔订单已成交"**：这些是演示库里灌的演示数据，不是真实成交。市场洞察里自己写着"真实成交 0 单"。这句话被追问会很被动。建议改成"演示环境已跑通全流程（订单、核销、结算、存证）"，并标注"演示数据"。现在库里是 1,608 笔，数字也已变化。
2. **旅豆单笔抵扣上限，三份材料三个说法**：产品参数中心里是 **10%**（`bean.deduct_max_pct = 0.1`，订单确认页也按 10% 算）；《口径指南》的标准答法写 10%；但《市场洞察》和 v4 第 12 页写的是"单笔最多抵 30%"。PPT 里必须统一，我这份方案按产品实际值写了 10%。如果你们打算改成 30%，要先改参数中心，再改所有材料。
3. **第 8、16 页的措辞**：出现了"区块链可信凭证""蚂蚁链开放联盟链"。按你们的口径指南，对投资人（L5）讲"合规成本构成与准入壁垒"，"区块链"一词属于"慎用"。建议统一成"联盟链存证""可信凭证"，并保留"链上只记事实指纹"这句。
4. **"增发权限已放弃"这句话**：口径指南的标准答法里有它，但当前生产用的是蚂蚁链内置存证，没有部署合约，也不发行任何可交易资产，所以这句已经对不上现状。建议改成"我们不发行任何可交易资产，链上只有哈希指纹"。

## 8. 被追问时的应答（Top 8）

| 问 | 答 |
|---|---|
| 你们是不是发币？ | 不发。我们发的是绑定实体消费的权益凭证，不能充值、不能提现、不能交易，12 个月过期，单笔抵扣上限 10%。两项国标允许的就是这个形态。 |
| 凭什么信你们？ | 三重可查：资金不落我们账户；每笔分账有存证、可公开复核；我们不发行任何可交易的资产，链上只有哈希指纹。 |
| 景区自己做不行吗？ | 能做内容，做不了分账：商户多、口径多、周期长，手工账必错。我们卖的不是剧本，是"这笔账谁也改不了"。 |
| 和 OTA 比，你们的差异？ | OTA 卖标品抽佣，不碰履约；我们组织场景、全程核销、按一单多方分账。两者不冲突，OTA 是潜在渠道甚至收购方。 |
| 为什么要用链？ | 不是为了"上链"，是让多方分账可复核。链上只放指纹，业务数据在自己的库里，是审计锚点，不是资产。 |

| 真实成交有多少？ | 现在是演示环境，没有真实成交。第一年只考核一件事：朱家角月单量到 2,654 并扛过一个淡季，跑不到就停。 |
| 最大的风险？ | 景区觉得"我自己也能干"，以及第二城复制不成立。前者靠把分账做到景区自己做不了；后者靠"第 2 城打平月数 ÷ 第 1 城"这条判据，>1.5 就停在第 3 城。 |
