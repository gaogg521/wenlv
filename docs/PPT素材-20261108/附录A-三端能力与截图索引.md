# 附录A　三端能力与截图索引

> 这是 [PPT方案-向往的自由.md](PPT方案-向往的自由.md) 的附录：三端有哪些功能、每个功能对应哪张截图。项目价值、玩法对比、为什么用可信凭证、逐页大纲，都在主文档里。

> 整理日期：2026-11-08。数据来自本机演示库（8080），截图是当天实际界面。
> 三端：**游客小程序**（mini-a）、**商户小程序**（mini-b）、**PC 运营后台**（`/admin-ui`）。
> 对外讲链上能力时，措辞请按《向往的自由-Web3对外表述口径与举证清单》；小程序界面里不出现"区块链/虚拟资产"字样，统一叫"权益凭证 / 可信记录"。

## 一页看懂

| | 谁用 | 一句话 | 规模 |
|---|---|---|---|
| 游客小程序 | 游客 | 找线路 → 下单 → 凭码入场 → 写笔记 → 攒旅豆与勋章 | 5 个底部入口 + 4 个分包，共 21 个页面 |
| 商户小程序 | 景区 / 民宿 / 体验店 | 扫码核销 → 看订单与库存 → 对账结算 → 攒经营等级与徽章 | 4 个底部入口，共 9 个页面，老板 / 店长 / 核销员三档权限 |
| PC 运营后台 | 平台运营、财务、审核、风控、城市合伙人 | 把前两端的内容、订单、资金、风控、存证全部管起来 | 10 个分组、50 个模块、9 种角色 |

三端共用一个 Node 服务；小程序上每个页面的内容，都能在后台找到对应的修改入口（后台"小程序装修与映射"页，页面映射由自动测试守护，漏登记会让测试失败）。

## 二、商户小程序

**核心链路：核销 → 订单 / 库存 → 结算 → 荣誉**

| 环节 | 能力 | 截图 |
|---|---|---|
| 工作台 | 近 7 日经营（核销数、订单流水；流水仅店长 / 老板可见）、扫码核销主入口、门店日常入口（订单 / 库存 / 对账 / 核销记录）、平台公告 | `商户端/01-工作台首页` |
| 核销 | 扫码核销、手动输码、剧本游"对暗号"核销；离线核销名单，恢复网络后回传，冲突进后台"离线核销冲突"处理；核销记录可按历史查看 | `02-扫码核销` `10-核销记录` |
| 订单 | 门店订单列表（搜索、状态筛选、按日期翻页）、订单详情（出行与履约信息、联系人脱敏、核销进度） | `03-门店订单` `04-订单详情` |
| 库存 | 按商品分组、搜索、历史日期筛选，展开看每个团期的价格、余位，可管理团期 | `05-库存与价格` `06-库存-团期余位展开` |
| 结算 | 周结算单、五项分账、逐单明细、"确认对账无误"或"金额有误，发起异议"、回单；退改手续费分成比例走参数中心 | `07-结算-周结算单` `08-结算-五项分账与确认` |
| 荣誉 | 经营等级与升级差距、徽章墙（商户等级 / 经营荣誉 / 可信勋章三类，已获得点亮、未获得显示进度）、可信凭证（每枚徽章对应一条可核验的记录） | `11-经营等级` `12-徽章墙` `12b-徽章墙-经营荣誉` `12c-徽章墙-可信勋章` `13-可信凭证` `13b-可信凭证-列表` |
| 入驻与账号 | 微信登录、商户自助入驻申请（平台审核）、凭邀请码加入门店、店员管理、门店码 | `14-我的门店` |

权限分三档（核销员 / 店长 / 老板）：核销员只做核销，看不到订单流水；店长和老板可看订单流水与经营数据，店员管理由老板负责。

## 三、PC 运营后台

入口 `/admin-ui`，登录支持强制首次改密与二次验证；按职责分 9 种角色（超管、运营、财务、内容审核、风控、城市合伙人、只读观察、运维、开发），菜单和落地页按角色下发，城市合伙人看不到系统与资金敏感模块。

**`PC后台-首屏/` 和 `PC后台-整页/` 体积大（约 38MB），没有入库，只在本机的 `docs/PPT素材-20261108/` 里。** 每个页面有两种图：`PC后台-首屏/` 是顶部一屏（3200×1800），`PC后台-整页/` 是整页长图（宽 2400，最长一张高 12194 像素）。文件名一致，按序号对应。

| 分组 | 主要能力 | 截图 |
|---|---|---|
| **经营总览** | 经营概览：GMV、日均、峰值、对比基数，待办与风险实时汇总，近 30 天趋势，经营分析卡 | `01-经营概览` |
| **商品与资源** | 商品与团期（线路资料、团期价格余位）、商户与进件（审核、资料、结算账户、等级徽章）、景区资源、供应商 | `02-商品与团期` `03-商户与进件` `04-景区资源` |
| **订单履约** | 订单管理（详情、受控修正联系人、客服备注、退款、未支付取消）、售后工单（认领 / 转派 / 办结 / 重开全留痕）、核销暗号、离线核销冲突 | `05-订单管理` `06-核销暗号` |
| **用户与权益** | 用户中心、实名认证、权益账户、徽章管理（定义与发放）、权益调整 | `07-用户中心` `08-徽章管理` |
| **内容运营** | 内容看板、审核队列、内容审核、举报与申诉、约稿任务、创作者池 | `09-内容看板` `10-审核队列` `11-约稿任务` `12-创作者池` |
| **合伙人与推广** | 合伙人中心、排行与对账、推广服务商、逐品佣金 | `13-合伙人中心` `14-排行与对账` `15-推广服务商` |
| **资金结算** | 资金工作台、结算、提现审批、现金加奖打款、协议变更、旅豆预算、共创分润 | `16-资金工作台` `17-结算` `18-提现审批` `19-旅豆预算` |
| **渠道装修** | 小程序装修与映射（首页文案、主题入口、目的地、客服协议等，保存后 5 分钟内生效；小程序页面 → 后台入口对照）、轮播、常见问题 | `20-小程序装修与映射` `21-轮播管理` `22-常见问题` |

| **系统治理** | 风控事件与案件、审计日志、安全中心、后台账号、参数中心（金额存分、比例存 bp、数值走参数中心）、功能开关、集成中心（支付 / 小程序 / 短信凭据加密落库）、运维控制台 | `28-风控事件` `29-审计日志` `30-后台账号` `31-参数中心` `32-运维控制台` |

## 五、PPT 排版建议

1. **三端关系图**：游客小程序 ⇄ 服务 ⇄ 商户小程序，PC 后台在中间管理，一张架构图配三行字。
2. **游客端一页放 3–4 张手机图**：首页、线路详情、确认订单、勋章墙，从"逛"到"成长"讲一条线。
3. **商户端一页放 3 张**：工作台、结算、徽章墙，讲"核销 → 对账 → 荣誉"。
4. **后台一页一个主题，用大图**：经营概览、订单、结算、小程序装修、存证中心各占一页，首屏图是 3200×1800，放大不糊；需要看整页内容时用 `PC后台-整页/`。
5. **可信存证单独一章**：用 `可信能力一页纸` 打底，再配公开复核页。

## 六、使用前请知道

- **小程序截图分辨率有限。** 游客端和商户端都是 234×507（模拟器在这台电脑上能显示的最大尺寸）。建议在一页里缩小到手机框大小使用，不要全屏铺满；需要更清晰的话，在更大屏幕上把开发者工具窗口拉大后可以重拍。
- **商户端是 2026-11-08 下午重新拍的**，用的是演示商户"安麓大夫第·朱家角"的老板视角，数据是演示数据。
- **商户端 `11` 到 `13` 几张经营等级页，顶部小标题显示成 "GROWTH &amp; TRUST"**，是页面上一个文字转义的小缺陷，还没修；做 PPT 时可以把顶部小标题那一行裁掉。
- **游客端订单类三张图（20 / 21 / 22）是早期录制**，页面风格与现在基本一致，但时间较早。当前测试账号没有订单，所以没有现成的新图。
- **游客端 `15-线路详情-集合点与须知` 里**，履约商户卡的营业时间显示成 "undefined"，这是页面上的一个小缺陷，还没修；这张图用在 PPT 上请先裁掉那一块，或换用 `13` / `14`。
