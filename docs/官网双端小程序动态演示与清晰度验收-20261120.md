## 一、需求与基线

负责人反馈：两个小程序截图在官网产品区不清晰，且希望不再是一张静态图，而是像 GIF 一样依次点击「首页 / 主题游 / 商城 / 笔记 / 我的」切换。

基线实测：

| 项 | 原状 |
|---|---|
| 游客端 `assets/visitor.webp` | 153×330，展示宽度 234–246px、最小高度 475px，接近 2 倍拉伸，文字发糊 |
| 商户端 `assets/merchant.webp` | 234×507，受最小高度约束轻微拉伸 |
| 交互 | `<img>` 静态图，无点击、无轮播 |

## 二、改动内容

仅改 `招商宣传站/site/` 三文件，未替换任何摄影原图：

- `index.html`：两个 `.phone` 内改为真实界面结构的 DOM 演示器。游客端 5 帧（首页 / 主题游 / 商城 / 笔记 / 我的），商户端 4 帧（工作台 / 订单 / 库存 / 我的），每帧含真实文案、状态与卡片；底栏为可点击菜单按钮（含 SVG 图标）。
- `editorial.css`：新增演示器样式段，按最新版小程序视觉复刻（游客端米色暖调 + 橙色强调，商户端紫色导航 + 棕色强调）；`≤1100px` 与 `prefers-reduced-motion` 适配。
- `app.js`：新增轮播逻辑——可见时每 2.6s 切一帧；点击菜单立即切换并暂停轮播 9s；`IntersectionObserver` 控制仅在区块可见时运行；`prefers-reduced-motion` 时保持首帧不动。无内联样式、无 `element.style` 写入。

**关于抓帧方式（如实说明）**：本机已确认微信开发者工具在 D 盘且 CLI `islogin` 返回 `{"login":true}`，但沙箱无法拉起 IDE 图形进程，自动化端口 9421 无监听，真实小程序截图/录像在当前环境不可得。因此本版使用**高保真 DOM 复刻**，视觉依据为负责人提供的 520×980 真机首页截图与项目内真机走查证据，文字与卡片均为矢量渲染，放大不失真。抓帧脚本已留在 `wanderlust/api/test/capture-site-mini-frames.mjs`，在能启动 IDE 的环境可生成真实帧后直接替换 DOM 帧内容。
