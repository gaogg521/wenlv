## 四、⚠️ 接手第一件事：修 package-tour 分包编译

**症状**：模拟器进 `/package-tour/pages/booking/index` 超时（`timeout waiting for automator response`），home 页正常。首页磁贴视觉升级时也踩过一次同症状（theme-grid 闭合标签被截断 → 修复后恢复）。

**根因（高概率）**：booking/index.wxml 保险卡片用了复杂表达式，违反手册铁律"**分包 WXML 只做取值 + 单三元**"：

```
wx:if="{{p.insurance_fee > 0}}"        ← 比较表达式
¥{{p.insurance_fee / 100}}             ← 算术表达式
wx:if="{{priceSummary.insurance !== '0.00'}}"
```

静默编译失败 → 整个 package-tour 分包注册不上 → 导航超时。

**修法（照 sessView 的既有模式）**：
1. booking/index.js 的 getTourDetail 回调里预计算：`hasInsurance: Number(d.insurance_fee) > 0, insuranceFeeYuan: (Number(d.insurance_fee)/100).toFixed(2)`，setData 进 `p`
2. wxml 改为 `wx:if="{{p.hasInsurance}}"`、`¥{{p.insuranceFeeYuan}}`
3. priceSummary.insurance 的 `!== '0.00'` 判断同理（预计算布尔 `showInsRow`）
4. 修完跑 wxml 配平检查（`matchAll(/<\/?view[^>]*>/g)` 计数），然后 `cli quit → auto` 重启模拟器验证 booking 页能进
5. 走查截图（create/square/booking 三页）→ PR → 部署演示（先备份，迁移 V67）

**为什么测试全绿但模拟器挂**：后端接口和 JS 逻辑都是对的（459 项断言过），只有 WXML 表达式是编译期问题——`npm test` 覆盖不到。这正是清单 §"分包导航挂死"教训的重演。
