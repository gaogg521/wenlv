### 4.2 卡点：package-tour 分包编译失败（模拟器进 booking 页超时）

**症状**：模拟器 home 页正常，`reLaunch('/package-tour/pages/booking/index?id=1')` 报 `timeout waiting for automator response`。这正是 CLI 手册坑 #7 的表现：**分包 WXML 有复杂表达式 → 静默编译失败 → 整个分包注册不上 → 导航超时且无报错**。

**高概率根因（本次新增的保险卡片表达式）**——booking/index.wxml 中这三处违反"分包 WXML 只做取值+单三元"铁律：

```
第 39/40 行：wx:if="{{p.insurance_fee > 0}}"     ← 对象属性比较表达式（wx:if）
第 43 行：  ¥{{p.insurance_fee / 100}}/人          ← 算术除法表达式
第 57 行：  wx:if="{{priceSummary.insurance !== '0.00'}}"  ← 字符串不等比较
```

**已完成的修复（在 WIP 工作区，未提交）**——照页面既有 `sessView()` 模式（booking/index.js 第 59-67 行）预计算：

1. booking/index.js 的 getTourDetail 回调里、`this.setData({ p: d, ...` 之前插入：
   ```js
   d.hasInsurance = Number(d.insurance_fee) > 0
   d.insuranceFeeYuan = (Number(d.insurance_fee) / 100).toFixed(2)
   ```
2. wxml 三处改为纯取值：`wx:if="{{p.hasInsurance}}"`（×2）、`¥{{p.insuranceFeeYuan}}/人`、`wx:if="{{priceSummary.showInsRow}}"`
3. updatePrice 的 priceSummary 里加 `showInsRow: ins > 0`
4. 已验证：booking/index.js `node --check` 通过；wxml view 配平 OK；wxml 中再无新增复杂表达式（余下两处 `{{item.left_seats > 0 ? …}}`、`{{selView.info.end_time ? …}}` 是**改造前就存在且页面一直正常**的单三元+字符串拼接，不是嫌疑对象）
