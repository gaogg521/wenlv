# 景区经营跟进：申请、审批与登记

Codex 接手朱家角闭环最后一步。PC「景区资源 → 景点数据 → 经营跟进」以本人保存的复盘发起续约、采购或预算追加申请。采购和预算需填金额，按整数分保存；续约金额可空。每份复盘每种类型一条申请。同类再次申请需先保存一份新复盘。V83 按景区和复盘保存申请，并用已有审计日志记录动作。

申请由财务或超管中的非申请人批准或退回。审批通过后运营、财务或超管登记实际办理的合同、采购或预算单据编号及说明。申请、批准、退回、登记都有明确状态和原复盘编号。已审批结果和已登记凭据保留，重复操作被拒绝。审批和登记为内部业务流转，合同签署、采购执行和资金审批/付款走相应业务渠道。

城市合伙人只可访问授权城市、本人发起的记录。服务端的主体方接口校验绑定景区或有效商户和复盘所属商户。商户/景区独立 PC 身份的页面入口仍由 GLM 随 R2 接入。本次保留其在做的结算、异步退款、主体看板、贡献与成长值工作。

## 验证

在 8192 隔离库升级 V83。专项 `node --env-file=<隔离环境> test/scenic-followup.mjs` 覆盖跨城、使用他人复盘、无效金额、并发去重、申请方不得审批、待审不可登记、退回、重复办理拒绝及三条审计。Chrome 实际以城市合伙人发起 ¥99.88 的采购申请、财务批准、运营登记模拟单据 QA-PC-001。该单据为隔离验收记录。共享 8080 维持原验收版本。
全量 npm test、隔离 npm run test:db 及经营跟进专项均退出 0。
