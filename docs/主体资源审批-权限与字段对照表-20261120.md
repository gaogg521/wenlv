## 2. 渠道与权限版本

- 权限唯一判定来源:服务端逐请求读库解析(基线 ∩ grant);`subject_perm_grant` 支持 `subjectType/subjectId(NULL=全部)/staffRole/accountUid/channel(pc|mini|all)/resKind/action(*或具体)/fieldGroup/effect(1允许·可带字段组收紧|0拒绝)`;**拒绝优先**,grant 不能凭空扩权。
- 下发版本:`subject_perm_version` 单行递增;各端登录/回前台/权限被拒时刷新快照,仅更高版本覆盖本地(乱序响应不恢复旧授权);小程序提交携带 `X-Perm-Version`,落后返回 2101,端侧刷新快照后重放。
- PC 账号授权变更联动 `token_epoch+1`(旧会话 1002 重新登录);grant 变更同理针对目标账号。

## 4. 差异与通知的字段投影规则

- 差异三列(当前正式值/提交基线/拟生效值)按字段组着色;重点差异(price/stock/schedule/status/policy/contact/address)标「重点」,批准弹窗须逐项勾选确认。
- 敏感投影:`subject_resource_request` 不落 account_no/证照号/合同等专管字段(sanitize 在入口即拒,AC11 断言银行账号原文不得出现在申请快照);`platform_inbox` 通知只含申请号/对象/结论与原因摘要。
- 影响说明(impact_note):update 类申请命中任一重点影响时**必填**(受影响时段与既有订单处理说明);create 类不要求。
- 版本簿:审批生效走 entity save / 库存直写,同一事务写 `master_data_version`(source=subject-approval)与 `audit_log`(module=subject-request:submit/withdraw/preaudit/reject/effective + approval:<审批人>)。

## 5. 运营三类职责与页面入口

| 职责 | 页面/入口 | 常规动作 | 须超管或确认 |

| 商品与资源 | 运营工作台 → 审批页(subjectapprove) | 预审、提醒补材料 | 批准/退回=subject.approve 授权 |
| 内容与渠道 | 审核队列(reviewqueue)/内容/举报申诉 | 认领、判定、处理 | 公开发布/撤下、补贴预算规则 |
