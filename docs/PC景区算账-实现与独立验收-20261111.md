# PC 景区算账实现与独立验收

结论：本次 PC 景区算账与指定朱家角隔离链路通过验收。

入口在景区「景点数据」、商户「全景」和城市合伙人「查看对账」的详情中。点「❓ 经营测算」先看公式和口径，再打开独立测算弹窗。服务端使用已核验的整数分和基点公式，计算收益、单笔贡献、最低盈亏平衡单量、四条路径和敏感性表。页面展开公式显示代入值、各项结果、取整口径及版本。可将当期订单量和客单价带入情景，按最新数据重算或保存复盘。

实际经营按付款日期及当前关联景区商品汇总整笔订单。可展开来源码、订单号、支付、核销凭证数、退回现金、权益、结算编号及状态，同景区复购保留首单号。内部角色可查看确认成本、有效佣金记录和后台原订单。汇总区显示商品现金、已成功退款和净实收。退款含代收且缺少拆分时显示待核实。结算编号供源单核对，结算单覆盖的整期金额不归为单个景区收入。

复盘由 V80 保存版本、输入、范围、结果及来源记录。保存时重新验证本次数据指纹，变更时提示重算。仅具名账号可保存，历史按所有者、当前角色和景区授权读取。运营、财务、超管及本城合伙人可访问，城市合伙人不显示内部成本或佣金。

验收在本机隔离 API 8191、`wanderlust_codex_b34_20261111`、MOCK 支付完成。前置场景走已有推广归因、下单、出票、商户动态码核销、完成返豆及财务复核。专项测试再用首单所得权益发起复购并支付、保存和回看复盘，随后退款重算，并验证跨城和历史快照权限。复现命令为在 API 目录依次用同一隔离环境运行 `node --env-file=<隔离环境> test/scenario-populate.mjs` 和 `node --env-file=<隔离环境> test/scenic-calculator.mjs`。

此次范围为 PC 景区算账、复盘与朱家角链路验证。商户和景区独立 PC 身份授权、跨商家分项结算、单独二销/贡献确认、预算再投入及真实微信和银行通道仍待后续交付。第三、四批此前退回项继续独立跟踪。

## 经营详情入口调整与复验

- 景区列表和后台导航没有单独的算账操作。景点数据、商户全景及城市合伙人对账详情的「❓ 经营测算」先打开简短公式和口径说明，再打开测算弹窗。关闭保留原详情及页面，键盘焦点回到入口。实际数据日期与月度测算假设分区。带入实数为用户显式操作。
- 景区视角统计该景区关联商品。商户全景只列该商户在本城关联的景区，后端在景区口径上再按订单商户过滤，历史复盘与整景区复盘隔离。城市合伙人对账仅列所选授权城市景区，内控成本和佣金沿用既有屏蔽。现有独立商户及景区 PC 身份仍待接入。
- 隔离后台用超管打开景点数据、运营打开商户全景、青浦城市合伙人打开城市对账，逐一点击说明、打开测算、查看两类数据、关闭及核对原页和焦点。三个账号的实际路径均通过。专项以同景区两家商户补验订单范围、复盘范围及跨城访问。
- 本次复验的 npm test、完整隔离 test:db、景区专项均退出 0。本机 8191 可查看，8080 本轮未部署。
