范围：两小程序＋PC 后台方案的第一批，即 B16 基础授权、B10、B15 本批规则/质量核对改进、B08 明细契约设计、B12 现有信息聚合。自由豆 B17、套餐 B01–B04、完整销售工作台 B05–B08 及合作资金查询 B13 不在本批完成范围。

## B08 下一批明细契约

本节是接口设计，不代表这些接口已发布：

- 本人佣金列表：建议 `GET /c/promote/commissions?page=&pageSize=&status=&from=&to=`，返回总数及分页、关联订单/产品、计佣基数、快照费率、金额、观察期/放行/冲正状态、时间。服务端从登录用户限定范围，禁止请求参数指定其他推广员。
- 本人提现列表/详情：建议 `GET /c/promote/withdrawals`、`GET /c/promote/withdrawals/:id`，返回申请编号、金额、审批与付款状态时间线、原因、账户尾号、登记付款/回单入口。当前旧状态0待审、1已登记付款、2驳回，不能直接把1改成“待付款”。
- 待付款状态新增时同时迁移历史映射、资金占用、日限额、并发申请及冻结守卫；审批通过与实际付款登记分开。真实到账须有外部证据。
- 回单下载：本人所属业务单逐次鉴权后返回文件；不得复用后台查询权限或给出公开静态银行资料地址。
- 时间/状态参数白名单，pageSize上限，跨页计数同源；汇总区分观察期、已放行、待处理占用、可申请、已登记付款和冲正。实际最低门槛、观察期与维护开关来自参数中心。
- 合作分润不是推广佣金：后批合作查询按 subject_grant → subject_resource → co_creator/项目取范围；门店结算仍按 merchant_staff，不把三种资金合并成余额。

## 验证

- 全新隔离库 `wanderlust_phase1_20261110`、端口8096，迁移执行成功；没有使用演示库运行破坏性测试。
- `npm run test:phase1`：客户端运行级验证及10组HTTP/数据库专项通过。覆盖越权、到期、撤权/冻结、门店岗位变化、跨端令牌拒绝、微信会话身份关联、截止与名额、内部字段隔离和推广规则。
- `npm test` 退出0；`npm run test:db` 退出0。重复回归发现既有 cross-end 测试未显式准备出发日，修正夹具为合法核销日并在结束恢复，不放宽服务端核销日期守卫。
- PC 浏览器实际登录，完成主体创建、资源关联、用户查找和经办授权；打开产品经营总览检查真实渲染及配置来源。
- 微信开发者工具可确认已登录，但本轮临时模拟项目先出现 `No context found for objectId`，重启自动化后又停在 AppID 权限拉取；没有取得可靠的小程序截图/真机验收。客户端行为以VM运行检查及同源HTTP专项验证，不能将其表述为模拟器/真机全通过。可用 `api/test/phase1-mini.mjs` 在自动化恢复后补验，必须指向隔离项目和隔离库。

原始测试日志保留在交接目录「第一批验收-20261110」；后续运行需要先重新核对环境，不把日志当成未来版本的验收证据。

## 使用与后续边界

后台入口：合伙人与推广 → 合伙人中心 → 主体与经办授权（仅超管）。合作授权为只读，门店岗位另选门店及核销员/店长/老板；两者不会相互推导。

本批增加资料核对提示，不自动替运营虚构或批量覆盖既有商品内容；发现标题/天数、商城单位和资源关联问题时，经营总览提供核对建议并可进入原资料编辑器。真实商品资料仍须业务核实。

未上传微信体验版/正式版。真实跨AppID绑定依赖微信返回有效统一身份，真实付款/扫码/回单仍须外部条件验证。全量项目状态请看执行台账，第一批完成不代表B01–B17全量完成。
