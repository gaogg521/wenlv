## 2. 环境与启动

```bash
cd api
npm ci
npm run migrate                          # 新库从头执行；已有库只补跑未执行的版本
JWT_SECRET=dev PASS_SECRET=dev npm start # 本地开发库用；后台 http://127.0.0.1:8080/admin-ui，admin / admin123
```

Windows PowerShell 写法：

```powershell
$env:JWT_SECRET='dev'
$env:PASS_SECRET='dev'
npm start
```

**演示环境（本机 8080，库 `wanderlust`）不要用上面的命令启动。** 在 `api/` 目录用：

```bash
node --env-file=.env src/index.mjs
```

演示库的密文分属两把主密钥，统一的事负责人说先不动（2026-11-06）：

| 启动方式 | 能解开 | 解不开 |
|---|---|---|
| `--env-file=.env`（当前用法） | 蚂蚁链凭据、当前链设置、数字身份密钥（14 条） | 邮箱配置（5 条）、订单联系电话（40 条） |
| `start-8080.cmd`（`JWT_SECRET=dev`） | 邮箱配置、订单联系电话 | 上面那 14 条：当前链退回「未接入」，数字身份页接口报错 |

所以：不要用 `start-8080.cmd` 重启演示，也先不要往演示库写新凭据（会继续分裂）。两种方式的 `PASS_SECRET` 也不同。只读核对用 `node --env-file=.env scripts/secrets-key.mjs check`；`rotate` 要求全部能解开，不能直接拿来统一。

要点：

- **`SECRETS_KEY`**：后台保存的凭据和手机号、联系电话都用它加密（AES-256-GCM）。未设置时由 `JWT_SECRET` 派生，换 `JWT_SECRET` 就解不开。生产必须设：用与服务相同的 `JWT_SECRET` 运行 `node scripts/secrets-key.mjs current`，把输出原样设为 `SECRETS_KEY`。格式错误会拒绝启动。
- **生产环境（`NODE_ENV=production`）的默认密码护栏**：`admin123`、`city123` 不能登录；首次建账号没配 `ADMIN_INIT_PASSWORD` 时随机生成、只打印一次；不种演示城市账号。被拒登后用 `node --env-file=.env scripts/admin-reset-password.mjs <账号>` 换临时密码。
- **`BIZ_TZ`**：业务时区，默认 `Asia/Shanghai`。旅豆日终根、退改天数都按它切日。
- **`PUBLIC_BASE`**：对外访问基址。真机调试和外网访问必须设置成 HTTPS 域名。
- 链凭据和当前链在后台「可信存证 → 链接入」保存，环境变量只作兜底。

演示数据（**会清库**，必须指向隔离库）：

```bash
DB_NAME=wanderlust_qa npm run seed:scenario
```

小程序用微信开发者工具打开 `mini-a/`、`mini-b/`。CLI 自动化看 `docs/CLI调试-AI交接手册.md`。

## 3. 测试（改完必须跑）

```bash
cd api
npm test                                                          # 不设 PORT 时只做静态扫描，不碰演示服务
DB_NAME=<隔离库> PORT=<端口> API_BASE=http://127.0.0.1:<端口> npm run test:db   # 需要隔离服务在跑、同一 JWT_SECRET
npm run test:chain                                                # 链上完整性，只能在全新隔离库上跑
```

完整套件清单在 `api/package.json`。

推荐一次跑全：建全新隔离库 → `node scripts/migrate.mjs` → 起隔离服务（用空闲端口）→ `npm run seed:scenario` → `npm test` → `npm run test:db` → `npm run test:chain`。

踩过的坑：

- **一定要固定 `PORT` 和 `API_BASE`**，否则部分测试会连到演示服务 8080。
- **看退出码，不要只看输出**：`npm test` 是一串 `&&`，中间一步崩了后面就不跑；用管道或脚本时要确认退出码是 0。
- **测试守卫**：会写库或清库的脚本调用 `test/_guard.mjs`，`DB_NAME` 没设或指向 `wanderlust` 会拒绝运行。
- **`test:chain` 要全新库**：已锚定批次有触发器保护、不能回退，同一个库跑第二遍必失败。
- **测试必须可重复**，且收尾要清掉自己写的夹具（账本夹具没清曾让存证对账失败）。
- **小程序真实渲染**：把 `mini-a`、`mini-b` 复制到临时目录，副本 `app.js` 的 `apiBase` 换成隔离服务地址，`mini-b` 副本的 appid 换成 `mini-a` 的（`touristappid` 在 CLI 下起不来）；`cli auto --project <副本> --auto-port 9421`。**等首屏出来再 `reLaunch`**，否则自动化会话会崩。只在模拟器里看，不上传，仓库文件不动。
  - **商户端开发版演示登录**：在「我的」点「一键进入演示门店」，固定 `mock-chenjie` / 门店1 / 店长角色2，进入工作台；令牌过期自动保持演示身份重登，退出清除演示模式。入口仅开发版连接本机/局域网HTTP显示，体验版/正式版不展示且调用被拒绝；后端生产环境继续拒绝 mock 登录。普通「微信登录」仍走真实 wx.login，不切换演示身份。清缓存或退出后重新点演示按钮即可，无需控制台注入。隔离库若没有此演示账号，需单独准备固定模拟身份和门店绑定，不能依赖演示库账号存在。
  - 渲染时量版式比猜准：`page.$(sel).size()` / `.offset()` 能拿到实际宽度和位置（#160 就是这样量出按钮被挤出卡片的）。`mini.screenshot` 要等页面画完再截，截到纯黑多半是首屏没出来。
- **Windows / Git Bash**：heredoc 会吃掉反斜杠，写正则用文件；`node` 跑 `/pages/...` 路径前加 `MSYS_NO_PATHCONV=1`。

## 5. 红线与约定（违反会出事）

1. **小程序不出现区块链 / 虚拟资产用语**，例如：区块链、上链、存证、锚定、NFT、藏品、Token、钱包、哈希。
   - 小程序界面统一用"可信记录 / 校验码 / 封存"。
   - 后台和对外 H5 不受此限。
   - `npm test` 会把关；后台录入小程序可见字段时也会拦截。
   - 新增小程序可见字段时，记得加进 `entity-schema.mjs` 的 `PUBLIC` 或 `MINI_EXTRA`。
2. **游客接口只下发白名单字段**。
   - 不要再写 `return { ...p }` 这类把整行返回给 `/c` 的代码。
   - 历史上曾因此把商家暗号下半句、佣金费率、合同编号泄露给游客。
   - 新增游客可见字段时，加进 `PUBLIC`，或加进 `GET /c/tours/:id` 里的 `PUB_COLS` / `PUB_PROFILE`。
3. **金额一律存"分"，比例一律存"万分比（bp）"**。业务数值走参数中心（`cfg` / `cfgNum`），不要写死在代码或页面里。
4. **存证**：
   - `canonical` 只放白名单字段，不含个人信息。
   - 在事务里调用时传事务连接 `conn`。
   - **永远不写假交易号**。
   - 状态含义：0 待打包、1 已打包、5 已提交待确认、2 已锚定、3 重试、4 人工处理。
   - 已锚定批次不可回退（有触发器保护）。
5. **新增链适配器**：
   - 配置项一律通过 `E.XXX` 读取，不要用 `process.env`。
   - 在 `index.mjs` 的 `PROVIDERS`、`CATALOG` 里登记。
   - 实现 `anchor`；能核验就实现 `confirm` / `probe` / `selfTest`。
   - `capabilities` 如实声明。
   - 写本地假服务测试，参考 `test/chain-hub.mjs`。
6. **迁移只增不改**。下一个编号看 `api/db/migration/` 最大号加 1，不要修改已执行过的迁移文件。
7. **测试不要调用 `reanchorPending()` / `confirmPending()` 去处理全库**：它们会把真实批次锚到测试用的假链上，曾因此污染测试库。只锚测试自己建的批次。
8. **不要用脚本做字符串替换去批量改源码**（`archive/` 里那批补丁脚本就是反例）。直接编辑源码，用 git 记录。
9. **小程序新增页面时，必须同时在 `api/admin/miniapp.js` 的 `MINI_MAP` 登记**：写明页面上有哪些内容、在后台哪里改。否则 `npm test` 失败。
10. **新增后台页面**：
    - 页面函数写在 `admin/pages/` 对应栏目文件里（新文件要在 `index.html` 里按顺序加 `<script>`，放在 `core.js` 之后、`workspace.js` 之前）；
    - `src/domain/modules.mjs` 登记模块（菜单和页面标题取自这里），并同步 `test/admin-modules.mjs` 的基线；
    - `src/domain/admin-modules.mjs` 给新接口映射模块；
    - `workspace.js` 的 `renderers` 与 `descriptions`，`operations.js` 的 `ADMIN_PAGE_OPERATIONS`。
    后台脚本是普通脚本、共享全局作用域：不同文件里不能有同名的顶层 `const`/`let`，加载时立即执行的代码只能用先加载文件里的东西。
11. **用户手机号只经过 `api/src/infra/mobile.mjs`**：
    - 写入用 `bindMobile`，按完整号码查找用 `whereMobile`（走 `mobile_hmac` 盲索引，未迁移的历史明文行兜底），展示用 `maskMobile`。
    - 不要再写 `Buffer.from(phone)` 直接存、直接比，也不要把完整号码放进任何接口响应或日志。
    - 同一手机号只能绑一个账号（`mobile_hmac` 唯一索引），重复绑定给业务错误。
12. **冻结账号的资金动作要暂停**：新增任何会给用户放行、提现、打款的动作，都要先看账号状态（`promo.isUserFrozen`）。佣金放行在 `promo.settleDue`，提现打款在 `POST /admin/withdrawals/:id/verdict`。冻结期间佣金继续累计但不放行，驳回提现不受限。
13. **发行方密钥、DID 盐不能重新生成**：解不开就报错，不要为了让页面恢复去覆盖，否则全体 DID 变化、已签凭证全部失效。
14. **不要主动部署合约或把当前链切到合约模式**（§1）。上真实链的内容公开且不可删除，只上指纹，不上个人信息和金额。
15. **链路视图的高度有上限：最多 3 行、每行最多 10 块，一页 30 块**（`admin/pages/web3.js` 的 `chainPlan`）。
    - **块的尺寸固定**：块宽（含说明）封顶 132px，块少也不放大；说明只有标题、月日、事件数、环节标签（md 2 个 / sm 1 个）、状态，哈希在悬停卡里。
    - **行数尽量少、每行尽量多**：依次试 1 行、2 行、3 行，块宽不低于 96px 的第一个方案就用；3 行也放不下才缩到小号（每行 10 块）。
    - 窄屏放不下 10 块时按宽度折行，行数才会超过 3。别再回到"批次多就一直加行"的做法。
16. **区块详情有两种，别混**（`openBlock`）：
    - 业务区块的叶子是 `attest_event`，表里列事件，「验证」调 `GET /admin/attest/verify`（重算指纹 + 沿证明路径算根）。
    - **账本日终块的叶子是当天的旅豆流水（`bean_ledger`），不是业务事件**，`GET /admin/attest/batch/:id` 对它永远回 0 条；要列流水并重算根，调 `GET /admin/attest/bean-day/:date`（`attest.beanDayDetail`）。叶哈希只在 `attest.beanLeafHash` 一处定义，封存和重算共用。
    - 指纹 / 根 / 交易号一律用 `hashCell`（缩略 + 悬停全文 + 复制）或 `hashFull`（64 位完整）显示，不要再 `slice(0, 12)`。
17. **小程序里的「记录编号 / 校验码」= 这条记录指纹（SHA-256）的前 8 位大写**（商户端勋章、游客端可信记录）。链上只有批次根，没有单条记录，所以不能拿它去链浏览器搜。核对入口是公开复核页 `/verify`（`mode=t1` 是不出现「链 / 存证」字样的口径）：输入订单号、账本日期或 8 位记录编号都行，编号走 `GET /open/verify/record/:code`——**只认勋章和订单两类**，只回类型 / 名称 / 日期和可本地重算的证明，不回业务单号、用户或商户 id、金额；其他类型（提现、实名、结算…）不对外按编号查。商户端「可信凭证」每张凭证有「复核」按钮，跳到小程序原生页 `mini-b/pages/proof`（不用 web-view，所以**不需要配置业务域名**，只走已配置的接口域名）：查 `/open/verify/record/:code`，只显示类型 / 名称 / 日期 / 封存状态 / 校验结果，页面**不读接口的 `note` 字段**（里面有「锚定上链」，小程序红线）。校验结果是服务端算的；要自己再算一遍，页面可复制 `/verify?mode=t1&no=<编号>` 链接用浏览器打开。游客端没加这个入口。

## 6. 常见任务怎么做

**给某个实体加字段**：在 `entity-schema.mjs` 对应实体的某个 section 里加一行。

- 存储位置：`store` 不写时默认存 `profile`，写 `'col'` 表示真实列，写 `{json, key}` 表示 JSON 列中的键。
- 后台编辑器、校验、审计、完整度统计会自动生效，不需要迁移、不需要新接口。
- 游客需要看到的字段：加进 `PUBLIC`，再在小程序页面渲染。

**加一个业务参数**：

- 新迁移里写 `INSERT IGNORE INTO rule_config (k, v, group_name, sensitive, memo)`。
- 同步加到 `src/config.mjs` 的默认值表。
- 需要校验的，在 `POST /admin/config/proposal` 里加校验（参考 `order.refund_policy` 和 `settlement.refund_fee_merchant_pct`）。

**加一个小程序页面**：

- `app.json` 登记页面。
- 准备 `.json` 文件，内容至少是 `{}`，**不能是空文件**。
- 在后台映射 `MINI_MAP` 登记。
- 文案走装修配置（`site`）或接口下发，不要写死。

**接一条新联盟链**：

- 优先用"通用网关"适配器，在后台配置路径、请求体模板、签名算法、返回字段位置即可。
- 只有对方接口实在无法用配置描述，才新写适配器。
