# ZCode 三端产品 UI 打磨任务单与 Codex 验收清单

2026-11-16 · 执行人 ZCode · 今日完成全部任务并一次性交验 · 独立验收 Codex

## 1. 目标、基线与优先级

本轮把旅行笔记做成游客能直接发现和浏览的内容入口，并改善付款前价格解释、店长当天的履约任务以及运营连续办理。UGC 作品曝光是本轮重点。ZCode 在 2026-11-16 当天完成本文全部待办、自测与证据整理，使用同一个 PR 和最终提交 SHA 一次性交给 Codex。任务编号和优先级用于定位与验收，全部任务均为今日交付范围。

- 开工时以最新 `origin/main` 为准，记录完整 SHA。本单编写时主线为 `1db1c76`，8080 走查基线为 `74897e2`（PR #209）。PR #207 已修实况、中文话题和景区入口。
- 保留现有「发布即得旅豆」文案和奖励规则，运营与创作者仍可理解审核、可见范围与奖励的实际状态。首页与创作中心都适用。
- 沿用游客端现有五个底部导航，保留创作中心的草稿、作品、约稿职责。UGC 展示内容来自已发布的公开作品，继续遵守现有审核、私密素材和所有权契约。
- 三端统一金额、状态和操作反馈的表达，保留各自视觉节奏。UI UX Pro Max 可用于查布局、对比度、触控、焦点与状态反馈，实际业务入口与交互以此单、仓库和走查为准。

| 任务组 | 今日必交范围 |
|---|---|
| A · UGC 重点 | 首页作品曝光、景区与线路相关笔记、广场浏览与发布 |
| B · 三端核心 | 游客价格解释、商户今日履约与结算、PC 审核和数据口径 |
| C · 可恢复与可运营 | 攻略图编辑恢复、库存分页、PC 成本与角色入口 |

## 2. A · UGC 作品展示与导流

### A1 首页直接展示公开作品

- [ ] 在主题卡片下方、常规商品流之前放「旅行笔记」区，替换原来只引流的窄入口。直接呈现至少两张作品卡，有条件时加可发现的「看更多」入口。不得以创作入口替代作品。
- [ ] 卡片优先显示已有封面、标题、已关联地点；无图片可用正文摘录构成文字卡，视频和攻略图采用已有可用封面或图卡。地点缺失时省略该行。点卡进相应笔记详情，点「看更多」进广场。
- [ ] 首次进入、返回、切换网络、部分封面失效分别可用。加载预留卡位，失败时可重试，空态保留明确的浏览/发布去处。首页其余内容独立加载。无头像或封面缺失的卡片仍可阅读。
- [ ] 用真实的已审核演示内容准备验收，至少有两个地点的已发布作品。选图正常、无测试占位标题，手机窄屏下长标题可读。启动后无需进入「我的」或「创作中心」就能开始浏览。
- [ ] 明确游客未登录的读取路径。允许匿名浏览时只下发公开卡片白名单，创建、点赞、评论等有身份动作按原流程鉴权；如已有登录门槛须保证首页其余内容正常加载，并在交验单说明门槛和验证结果。

### A2 景区、线路与笔记的双向关系

- [ ] 景区详情展示该景区的 2–3 条公开笔记，原「看这个景区的旅行笔记」进景区聚合页。线路详情展示该线路的 2–3 条公开笔记，显式区分线路关联与同景区推荐；如果采用景区补充，标题标为「同景区笔记」并防重复。
- [ ] 点卡打开笔记详情；详情有有效关联时分别提供「查看景区」「查看线路」，名称对应实际对象。缺少关联、下架商品或失效景区时不生成死链。保留中文话题与景区名称解码、聚合筛选和正常返回。
- [ ] 两个读入口均验证有作品、无作品、对象下架、网络失败。消费者返回线路/景区后能继续看团期或订购。以真实 ID 校验归属，推荐与排序结果可解释。

### A3 广场浏览、发帖、返回

- [ ] 广场首屏首先露作品。搜索、话题、当前景区筛选可见，「发笔记」从广场可直接进入现有 compose；浏览作品和管理草稿用各自入口。
- [ ] 搜索、话题、景区筛选有可清除及空结果态。打开作品、返回广场能保留当前筛选、已加载页和大致位置；选择发布后返回时保留原浏览条件，并按已有审核状态展示作品。
- [ ] 复用 `/c/notes/feed`、现有景区/详情契约和媒体选择器。若需新增线路查询或首页轻量接口，记录参数、排序、限制、鉴权和字段白名单，新增覆盖不同可见范围与过滤的专项验证。私密、审核中、驳回、下架含历史数据均不得出现在任何公开面；公开查询及卡片不可暴露作者私密媒体路径。首页只取所需条数，避免多页面重复拉取全列表。
- [ ] 回归 PR #207、#209 的中文聚合、私密实况、预览/封面跟随、空标题确认、手写标题和攻略图发布。只需要新增入口的地方复用原编辑器。

## 3. B · 三端核心任务

### B1 游客结算解释

- [ ] 在预订固定底栏同时展示预计实付和最主要的优惠原因。如朱家角示例「活动价 ¥298 · 旅豆已抵 ¥27 · 预计实付 ¥271」。明细列出活动费、折扣、自由豆、旅豆、保险（适用时）和应付，用户可回到对应控件调整。
- [ ] 金额读取现有试算结果，金额和优惠说明同步刷新；算价中明确反馈，失败可重试，支付按钮状态与试算一致。金额变动需提示，较矮手机、长金额、软键盘与底部安全区可用。
- [ ] 覆盖无优惠、只旅豆、只自由豆、两者叠加、团期/人数变更和报价失败。维持现有折扣、退款和返还口径。

### B2 商户工作台与结算

- [ ] 工作台首屏保留扫码核销主操作，在营收图之前展示今日待接待、待核销、临近截止、异常待处理。每项展示口径、数值或空态，点进去直达带日期/状态筛选的列表。店长与核销员分别验收，权限以现有配置为准。
- [ ] 「今日」的统计时区和筹备/履约口径要明确，与下钻列表一致；记录营收周期切换是否影响今日任务。
- [ ] 结算卡固定展示周期、订单数、调整净额、应结金额、当前动作。状态区分登记付款、渠道确认到账（如有）与待确认。试验至少一条有退款调整的账，从卡片能追到结算明细和对应订单。商户只见自身门店数据。

### B3 PC 审核办理与经营口径

- [ ] 保留审核认领、权限、批量规则和落账接口。队列支持单笔快速办理（推荐详情侧栏），处理后回到原筛选与位置；可连续处理下一条，有明确成功、失败和并发状态。详情和列表明确显示「仅自己可见」与审核状态。
- [ ] 复现演示中多条约稿出现约 498,564 小时的异常，核实时间字段和来源。未知时间显示「待核对」，异常不参与 SLA 排序；正常超时仍可定位。验证正常、缺失、错误、跨日和历史数据。
- [ ] 「热门主题游 TOP5」与范围保持一致。可改成「热销商品 TOP5」并支持品类区分，或严格限制主题游。核对真实列表中商城礼盒归类。最新订单明确按哪个时间排序，跨年显示年份。财务、超管和城市角色核对口径、数据范围、下钻。
- [ ] PC 键盘验收覆盖打开详情、处理、关闭、返回下一条；焦点可见，固定栏不遮挡操作；状态用文字辅助颜色。

## 4. C · 数据量与可恢复性

- [ ] **攻略图继续编辑**：草稿可恢复文字、样式及仍有效的素材。临时文件失效提示重新选择，生成失败可重试。仅保存攻略图草稿时不得误发笔记。复核用户正文与手写标题保留。
- [ ] **库存服务端分页**：支持门店范围、日期、状态与搜索，默认突出近期团期与余量紧张。数据量约两千条的门店下，首屏只取一页，加载后按选择条件查询；批量改价、改量、停售展示准确影响范围，相关实验用隔离库。
- [ ] **成本覆盖率**：资金工作台保留缺成本时毛利空值。展示覆盖比例、主要受影响商品及责任入口，财务能从清单追到对应订单或商品。缺成本不得按 0 计。
- [ ] **角色入口**：处理超管进入「主体方经营」只收到不可用提示的问题，按授权隐藏入口或明确只读预览。城市角色对无权科目显示「不在本角色范围」，有权且无待办才用「已清空」。对超管、财务、城市合伙人、商户/景区主体角色分别验证。

| A-03 | 首页进入朱家角笔记 → 景区 → 聚合 → 返回，再走线路反向路径 | 双向入口正确，中文名称与筛选命中真实作品，返回不丢当前上下文 |
| A-04 | 广场搜索话题，连续翻页，点开作品后返回，再点发笔记 | 搜索、清空、翻页和返回正确。创作入口能回到原浏览上下文 |
| A-05 | 验证首页空态、坏图及一次网络失败 | 首页主体加载，作品区明确反馈，可重试或继续浏览 |

| B-02 | 分别使用店长和核销员打开工作台并下钻待办，查看退款调整账单 | 首页数字与列表相符，门店权限保持，能追到原订单 |

| C-01 | 在攻略图生成前退出后恢复；模拟失效素材 | 文字和样式能恢复，失效提示明确，不误发 |
| C-02 | 大数据量门店切库存日期和状态，PC 查缺成本及各角色入口 | 请求量按页，结果准确，成本待办能落到条目，角色入口符合授权 |

**验收结论写法**：统一验收全套任务，逐项标「通过／退回复修／外部条件待验」，写明实测版本、环境、复现步骤及证据。全部可执行项通过后才可确认整体验收；公开内容门禁、首页作品曝光、双向路径或任一其他必交项失败，统一退回复修并记录缺口。
