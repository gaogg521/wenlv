# 蚂蚁链开放联盟链 · 存证落根合约（WanderlustRootStore）

> 一句话：链上只存「Merkle 根 / 前根 / 业务日 / 叶子数 / 序号」，只写不删、前根必须接上。
> 现状：**合约还没部署**。当前批次走链上内置存证（`DEPOSIT`），链上标识是交易哈希；部署本合约后才有合约地址，才能按合约地址/方法查询。

## 一、为什么选「区块链浏览器查询业务数据 - Solidity」这个模板

控制台「合约工程模板」有 6 个，逐个对我们场景的判断：

| 模板 | 判断 | 理由 |
|---|---|---|
| **区块链浏览器查询业务数据 · Solidity** | ✅ **选它** | 我们要的正是"把存证数据写进合约、外部人用浏览器就能查"。Solidity 方法 ABI 可读、调用方式统一（`chainCall` + 方法名）、工具链最成熟，出问题最好排查 |
| 业务逻辑数据浏览器展示 · wasm | ❌ | 模板规定了**固定交易数据格式**，我们要写自己的根结构；WASM 工具链比 Solidity 弱，调试成本高，收益为零 |
| 链上资产（发行、流转、查询） | ❌ **别碰** | 旅豆是**预付储值类积分**，一旦做成"可发行、可流转"的链上资产，等于变相代币发行 —— 文旅 + 微信小程序场景是监管高压线（微信侧明令禁止链上资产交易引导）。商业化也不靠这个 |
| 链上资产（管理） | ❌ | 同上，只是管理端 |
| 住房租赁积分管理合约（专业版） | ❌ | 行业模板（租房积分体系），与文旅不匹配，且要付费 |
| 多方签名决策交易（专业版） | ❌ | 治理/多签场景。我们的多方确认在**库里**（双人复核 + 审计日志）已经做完，搬到链上只增加成本和不可改风险 |

**结论：只开一个工程，选「区块链浏览器查询业务数据 · Solidity」，合约只做写根 + 查根 + 事件。**
不要业务逻辑上链，不要资产上链。链上越薄，越安全 —— 合约不可改，写错就是永久锁死。

## 二、合约做什么 / 不做什么

做：
- `writeRoot(root, prevRoot, bizDate, leafCount, seq)` —— 落一枚根；**同根重复写返回 false（幂等）**，不覆盖、不重发事件
- 强制 `seq = lastSeq + 1` 且 `prevRoot = lastRoot` —— **中间删掉一批，链上立刻暴露**
- `getRoot(root)` / `prevRootOf(root)` / `head()` —— 外部可逐步往前验证整条链
- `RootAnchored` 事件 —— 浏览器/索引器直接订阅

不做：
- 不放任何业务数据（订单号、用户、金额一律不上链），只放 32 字节指纹与四个标量
- 不做费率、权限矩阵、可升级代理（合约不可改，越复杂越危险）
- 不做资产发行与转移

## 四、迁移与兼容（重要）

- 已锚定的批次（演示库 #1~#3、隔离库若干）**不会重写**：它们的 `chain_provider=antchainopen`、交易哈希留在库里，仍走 `DEPOSIT` 方式验证。
- 新批次切到合约模式后，`attest_batch.chain_provider` 记成新标识（如 `antchainopen-contract`），**旧批次依旧按旧方式核验** —— 这是 `confirmBatch` 已支持的"按提交时的链核验"，不会误判。
- 切换前会先把 `attest_batch` 里待确认的全部清零，避免跨模式确认。

## 五、成本与容量（部署前确认）

- 部署一次：消耗燃料，具体数额部署后从「燃料管理 → 收支明细」看
- 每批写入：一笔 `chainCall`，gas 上限建议先给 `80000`（比 `DEPOSIT` 的 50000 高，合约写入比内置存证贵），跑通后按实际消耗下调
- 免费版 TPS=1：写入必须串行，现有适配器已按 1.1 秒间隔排队

## 六、验签口径（对外怎么说）

> 链上有我们自己的合约 `<地址>`。每一批业务数据的指纹（Merkle 根）都写进这个合约，
> 任何人不需要我们的系统，拿根去合约里 `getRoot` 就能确认"这批数据在这一刻存在且没被改过"，
> 顺着 `prevRoot` 可以一路验证到创世批次。业务数据本身不上链，链上只有 32 字节指纹。

**注意**：这句话只在合约真正部署并写入批次之后才成立。现在说，就是吹。
